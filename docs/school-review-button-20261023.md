# 학교 시험지의 검수 필요 문항 선택

홈의 `기출 등록 학교`와 `원본 시험지`는 모두 `sourceQuestions` 문항 화면으로 연결된다. 기존 선택 버튼은 등록 진행 상태 아래에 있었고 검수 대상이 없으면 숨겨졌다. 두 경로의 공통 화면에서 제목 오른쪽에 `검수 필요 문항 N`과 `모든 문항 N`을 항상 표시하도록 바꿨다. 좁은 화면에서는 제목 다음 줄의 오른쪽으로 배치한다.

문항 조회를 완료하면 기존 `needsUploadReview` 기준에 해당하는 문항만 먼저 보여 준다. 대상이 없으면 전체를 표시하고 0건 버튼을 비활성화한다. 선택된 버튼을 색과 `aria-pressed`로 구별한다. 전체/검수 대상 목록 모두 원문 번호순이며 페이지 이동과 상세보기의 문항 순서를 공유한다. 교사 검수·경고 확인 이력과 원문 데이터는 수정하지 않는다.

검증: `node tests/source-review-navigation-browser.cjs`는 실제 웹 빌드에 합성 로그인/API를 적용한다. 390/1280px, 홈의 학교/원본 시험지 진입 경로, 검수 대상 유무의 8가지 조합을 검사한다. 55문항을 두 페이지로 가져오며 서로 다른 조회 페이지의 2번/52번이 함께 표시되는지, 승인/경고 확인 문항의 제외, 전체 목록 50+5개와 원문 순서, 버튼 위치·가로 넘침·목록 복귀를 확인한다. `--live`는 같은 검사에 운영 정적 자산을 사용한다. 실제 회원 로그인·실물 휴대폰·운영 데이터 쓰기는 포함하지 않는다.

관련 단위 검사: `node --test tests/source-review-order.test.cjs tests/home-review-followup.test.cjs tests/mobile-ui-recovery.test.cjs` (13개).

공통 배포 검사와 자산 해시 결과는 배포 후 `release-records/school-review-button-20261023.json`에 기록한다. 설치 앱은 변경하지 않는다.
