모든 신규 웹 출력은 `image-pdf-cache.js`가 먼저 서버 슬롯을 확인하고, miss인 경우에만 선택한 section/mode의 DOM을 준비한다. `image-pdf.js`는 과거 `web-export.js`의 scale 3, PNG, jsPDF FAST 설정을 복원했다. 순차 렌더 후 canvas를 해제한다. 결합 출력도 페이지를 직접 순서대로 생성하며 기존 PDF를 다시 래스터화하지 않는다. 여러 모의고사는 각각의 PDF를 ZIP으로 제공한다.

서명은 서버의 부모 내용·문항 revision·순서·배점·제목·출력 설정·이미지 생성기 버전·워터마크에 기반한다. 단순 열람 시각은 제외한다. 직접 기출 출력과 내 시험지가 같은 슬롯을 사용한다. 캐시 재사용에도 접근권한 및 최신 세트 연결 확인 RPC는 실행되며, 문항 본문/풀이 조회나 DOM 준비는 실행되지 않았다.

실제 클릭 중 발견한 회귀도 수정했다.

- 제목 수정 후 이전 배치 제목이 PDF에 남는 문제: 입력 시 배치를 무효화하고 다시 준비한다.
- 여러 출력의 완료 팝업이 겹치는 문제: 중간 완료 팝업을 제거하고 `전체 출력물 2/2 · A3`처럼 현재 문서를 표시한다.
- 배치가 끝나기 전 PDF 버튼을 누르면 오류가 묻히는 문제: 준비 중 버튼을 비활성화하고 준비 이전 실패도 오류 팝업으로 알린다. 운영에서 비활성→활성 전환과 이후 다운로드를 확인했다.
- 6개월 만료의 UTC/한국시간 경계 차이: 기존 부모 보관 정책과 동일한 Asia/Seoul 달력 계산으로 맞췄다.

## 덮어쓰기·취소·보관·보안

일반 시험지의 별도 검증 사본에서 제목을 바꿔 재생성했다. 최종 slot ID/key와 metadata 행을 유지하면서 SHA가 변경됐고, PDF 제목도 실제로 바뀌었다. 최초 생성일과 만료일은 그대로였다. 390px 화면에서 생성 도중 취소한 경우 기존 SHA/updated_at이 유지되고 pending lease가 해제됐으며, 재시도 후 성공했다. 사용자 원본 시험지와 모의고사 버전은 바꾸지 않았다.

고정 key는 `<space>/image-pdf/<slot>/current.pdf`다. 서버가 actor/parent/variant/section/mode/watermark를 검증해 임시 업로드 권한을 발급한다. 실제 bytes의 SHA256·PDF header/EOF·크기를 검증한 뒤 기존 파일의 복구본을 확보하고 고정 key를 교체한다. DB update 실패/응답 유실은 토큰으로 재조정한다. 짧은 서명 URL과 no-store를 사용한다. 정상 갱신의 metadata 행과 final key는 증가하지 않는다. 운영 bucket 전체 object 개수의 전후 전수 집계는 미확인이다.

만료는 부모 created_at의 한국시간 달력 기준 6개월이며 다운로드/교체로 연장하지 않는다. 격리 SQL 시험에서 월말(8월31일→2월28일), 한국시간 날짜 경계, 권한·워터마크 분리, 만료·삭제·임시 객체 정리, 실패 복구와 경합을 확인했다. 운영 자료의 생성일을 조작하지 않았다. cleanup은 PDF 파생 키만 대상으로 하고 원본 문제/스캔/폼을 삭제하지 않는다.

## 진행 UI와 환경

페이지 수 미확정 시 계산 중 안내, 준비/페이지 생성/조립/R2 저장/파일 확인 단계를 표시한다. 페이지 진행 수와 완료 시 실제 시간·쪽수·용량·만료일을 표시한다. ETA는 출력 종류별 최근 성공 표본(최대 7개)과 페이지 처리 속도를 사용하며 정확한 초를 보장하지 않는다. 취소는 페이지 내 확인 버튼, 재시도·기존 파일·최소화 동작을 제공한다. 중복 요청은 기존 작업으로 연결한다.

Chrome 실제 운영 클릭, 모바일 폭390에서 긴 문서 생성 및 취소/재시도, 768/1024/1280에서 다운로드 메뉴 배치·가로 넘침 없음 확인. 일반 PDF 열기, 복원 인쇄, 청담중 목록 열기·인쇄가 완성 파일의 blob 탭을 열었다. 브라우저 PDF 뷰어 내부와 물리 인쇄 대화상자는 도구 접근 제한으로 미확인이다. `window.print()`로 PDF를 생성하지 않는다.

청담중 상세 생성 중 관측 JS heap 최대 표본은 100,551,864바이트, 무학중은 약73.7MB다. 이는 최고 브라우저 메모리 측정이 아니다. 실제 업로드 구간만의 시간 및 모든 준비 단계 시간은 이번 장시간 trace buffer 범위 밖인 자료가 있어 미확인이다. native 무학중 문제지929,320바이트 대비 이미지판은 약7.18배 크다. 성공한 native 전체 시간 표본이 없어 속도 비율은 비교하지 않는다.

Windows Edge, 실제 Android/iPad Safari, 설치된 앱의 모든 메뉴를 직접 클릭하는 검증은 미확인이다. 연결된 Chrome과 격리 Electron 결과로 다른 엔진을 성공 처리하지 않았다. 개별 메뉴의 모든 결합 조합·모든 인쇄 버튼을 각각 실행하지는 않았으며, 위 표에 없는 조합은 미확인이다.
