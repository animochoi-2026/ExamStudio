# 3차 파일럿용 기준 학생 및 게이트 예시 (최종)

## 기준 학생

**이 학생은:**
- 해당 과정의 정의·공식·정리·대표 유형을 다 배웠으나 70% 정도 이해했고 기억한다.
- 표준 계산과 대수 조작에서도 난이도가 올라가면 실수를 한다.
- 문제를 푸는 데 필수적인 조건이 3개 이상이 되면, 앞에서부터 하나씩 까먹거나 중간에 하나를 빼먹고 적용하지 못하는 실수를 한다.

## G_assembly 발동 예시 (조립 +1)

아래 중 하나라도 해당하면 발동을 검토한다:

- (2) `depends_on`으로 3개 이상이 사슬처럼 연결되어 있을 때. 중간에 쉬운 단계가 껴도 됨.
- (12) 중간 결과를 3개 이상 머릿속에 들고 있어야 다음 단계로 넘어갈 때. (예: "a값 구하고, b값 구하고, 그걸로 c 구해서...")
- (13) "이걸 알려면 저걸 먼저 알아야 해"가 3단계 이상 깊이로 들어갈 때.
- (19) 풀이 중간에 관점을 바꿔야 하는 지점이 2번 이상 나올 때. (예: 대수로 풀다가 기하로 바꿨다가 다시 대수로)
- (20) A→B→C→답 식으로 연쇄 추론이 3단계 이상일 때. (한 단계라도 끊기면 전체가 무너짐)
- (24) 한 문제를 풀기 위해 서로 다른 단원의 개념을 3개 이상 가져와야 할 때. (예: 합동 + 닮음 + 원의 성질)
- (30) 보조선을 그은 뒤, 그 보조선에서 다시 새로운 관계를 찾아야 할 때. (2단계 보조선)

## G_literacy 발동 예시 (문해력 +2)

아래 중 하나라도 해당하면 발동을 검토한다:

- (4) 문제를 푸는 데 꼭 필요한 조건이 3개 이상일 때. 앞에서부터 까먹거나 중간에 빼먹음.
- (5) 문제문이 4줄을 넘어가서 "앞에서 뭐라고 했더라" 하고 다시 읽어야 할 때.
- (6) 답이 숫자식이 아니라 문자식이라서, 구한 답을 선지랑 매칭하는 과정에서 헤맬 때. (예: "EG+FH" 같은 거)
- (7) 문제에 일상 용어나 게임 규칙이 나와서, 그걸 수학으로 번역하는 데 시간이 걸릴 때. (예: 주사위 게임, 말판)
- (41) 문제에 "단, ~는 제외한다" 같은 예외 조항이 2개 이상 있을 때.
- (45) 단위가 섞여서 변환해야 할 때. (예: cm와 m, 분과 시간)
- (47) 문제 상황이 2개 이상의 시간대로 나뉠 때. (예: "처음에는 ~였는데, 나중에는 ~")

## G_execution 발동 예시 (실행 +1)

아래 중 하나라도 해당하면 발동을 검토한다:

- (8) 경우의 수가 20개를 넘어가서 하나하나 세야 할 때. (예: 36가지 경우의 수)
- (9) 계산 과정이 5단계를 넘어가서 중간에 실수할 확률이 높을 때.
- (15) 경우의 수를 표로 그려서 정리하지 않으면 헷갈릴 때. (예: 2차원 표)
- (23) 경우를 나열하다가 빠뜨린 게 있는지 처음부터 다시 세어봐야 할 때.
- (58) 정수 조건을 만족하는지 5개 이상 하나하나 대입해봐야 할 때.
- (59) 전개한 식을 다시 묶는 과정이 2번 이상 필요할 때.
