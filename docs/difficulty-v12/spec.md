# 문제공방 난이도 평가 v1.2 통합 적용 요청서 (Codex 세션용)

> 2026-10-18 3차 파일럿 한정 변경: 기준 학생과 문해력·실행 게이트 해석에는 [사용자 제공 3차 문서](reference-student-gates-round3.md)를 우선한다. 이 문서의 계산식·스키마·스코어러는 유지한다. 조립 예시는 의존 구조 검토에 사용하며 실제 승급은 기존의 연결된 비자동 M2 이상 3개 조건으로 계산한다. 원문 요청서의 과거 학생·게이트 정의는 이 변경 기록과 구분해서 읽는다. 실제 모델 입력은 `app/difficulty-v12/prompt.json`에 보관한다.

> **이 문서 하나를 구현 지시의 완결된 기준으로 사용한다.**
> Part 1은 작업 순서·검증·실행 조건을, Part 2는 평가 기준·JSON·스코어러·테스트를 규정한다.
> 평가 정책과 구현은 이 문서에 통합된 내용으로 진행한다.
> **실제 파일럿에는 §2.4에 지정한 원문 이미지 3개의 실물이 별도로 필요하다.**
> 이미지가 없더라도 먼저 구현·코드 검증·파일럿 입력 준비·실제 프롬프트 작성까지 완료하고,
> 마지막에 필요한 이미지와 실행 승인을 한 번에 요청한다.

# Part 1. 작업 지시

## 1. 목적

Part 2에 확정된 난이도 평가 v1.2를 구현하여 다음 두 경로에 적용한다.

1. **데스크탑앱**: 문제 업로드 시 v1.2 기준으로 난이도를 평가하도록 연결한다.
2. **웹페이지**: 문제은행의 기존 문제 전체(약 1,300문제)를 재평가하는 기능을 준비하고,
   검증 및 실행 승인을 거쳐 기존 난이도(강사 수동 설정 포함)를 v1.2 결과로 교체한다.

**1차 완료 목표**는 스코어러 구현, 업로드 경로 연결, 전체 재평가 기능 준비,
코드 검증, 실제 프롬프트 승인 후 **파일럿 30문제 실행 및 결과 보고**까지다.
전체 재평가와 운영 점수 교체는 §2.3의 후속 조건에 따라 진행한다.

문해력 +2를 포함한 복합 난이도, V1의 T5 목표, 출제 의도에 따른 풀이 제한 등
Part 2에 정한 기준을 임의로 변경하지 않는다. 본문·JSON·코드·테스트는 같은 규칙을 적용한다.

## 2. 작업 내용

### 2.1. 평가 로직 구현 및 파일럿 준비 (Part 2 스펙)

- Part 2 §15의 결정론적 스코어러를 리포지토리 규약에 맞게 구현한다.
- 모델은 **GPT-6.1 Sol**, `reasoning.effort="high"`, 기본 AI 호출은 **문제당 1회**다.
  `strict_calibration=false`를 기본값으로 사용한다. JSON 및 모델 설정은 Part 2 §14·§20을 따른다.
- AI는 C/R/B/H 축, 경로 구조, E(`execution_load`), `literacy_high`,
  경로별 `execution_extreme` 및 판정 근거 등 Part 2 §14의 원시 필드를 채운다.
  **move class·기본 티어·승급 목록·경로 티어·최종 점수는 코드가 계산한다.**
  AI가 파생 필드를 출력해도 사용하지 않고 재계산한다.
- 승급은 G_assembly +1, G_literacy +2, G_execution +1을 독립적으로 적용하고
  중첩하되 T5를 상한으로 한다. 소수점 계산과 풀이 경로 선택은 Part 2 §7~§15를 따른다.
- Part 2 §17의 acceptance test를 코드 테스트로 구현하고 통과시킨다.
  §16 앵커의 고정 판정값을 이용한 스코어러 검증과,
  실제 원문을 모델에 입력하는 파일럿 검증을 구분하여 보고한다.

**프롬프트 실행 승인을 요청하기 전에 다음 준비를 완료한다.**

1. 스코어러 구현, §2.2의 업로드 연결, §2.3의 전체 재평가 기능 준비 및 코드 검증.
2. 은행 문항 22개 선정, 문항 ID·내용 버전·입력 매핑 준비, 외부 검증 8문항의 대상 번호 지정.
3. 실제 사용할 프롬프트 본문, JSON 구조, 모델·파라미터, 프롬프트 해시 준비.
4. 파일럿의 대상 목록, 기본 호출 수 30회, 예상 토큰·비용과 산정 근거 제시.
   아직 실측 전인 값은 추정치로 표시한다.

Part 2 §20에 따라 **실제로 적용할 프롬프트 본문을 보여 주고 파일럿 실행 승인을 받는다.**
이 세션에서 동일한 본문·설정과 실행 범위를 이미 승인받았다면 다시 묻지 않는다.
원문 이미지가 누락됐다면 위 준비를 완료한 뒤 §2.4의 필요한 파일을 모아서 요청한다.
승인과 입력이 갖춰지면 준비된 30문항 파일럿을 실행한다.

### 2.2. 데스크탑앱 업로드 플로우 적용

- 데스크탑앱에서 문제를 업로드할 때 공통 v1.2 스코어러로 난이도를 계산하도록 연결한다.
- **실질적으로 내용이 바뀐 문항만 재분석**하는 정책을 유지한다.
  동일 내용 재업로드는 **동일 평가 입력 버전으로 평가된 결과가 있을 때만** 재사용한다.
  다른 기준의 과거 점수나 수동값을 새 평가 결과로 재사용하지 않는다.
- 파일럿 검증과 연결 확인은 §3.1의 코드 검증 범위에서 수행한다.
  준비 단계에서 불필요한 유료 AI 호출을 발생시키지 않는다.

### 2.3. 웹페이지 전체 재평가 준비·실행 및 운영 점수 전환

문제은행의 기존 약 1,300문제 전체를 v1.2로 재평가할 수 있도록 대상 조회,
백그라운드 큐, 결과 분리 저장, 재개 및 운영 전환 기능을 준비한다.
강사 수동 설정도 최종 교체 대상에 포함하되, 새 평가가 완료되기 전에 기존 점수를 비우지 않는다.

**실행과 전환 순서**

1. 기존 평가의 점수·수동 설정·문항 버전을 백업한다. 백업은 복구와 전후 분포 비교에 사용한다.
2. 기존 활성 점수를 유지한 상태에서 승인된 파일럿 30문제를 실행하고 결과를 별도 저장한다.
3. 파일럿을 §2.4의 기준으로 판정하여 결과를 보고한다.
   **파일럿이 불합격이면 전체 실행을 중단한다. 사용자 승인 없이 프롬프트나 상수를 바꾸거나,
   변경된 기준으로 유료 재실행하지 않는다.**
4. 파일럿 합격 후 실제 토큰 사용량을 바탕으로 전체 대상과 남은 호출 수·예상 비용을 산정한다.
   **이 비용과 실행 범위를 승인받은 뒤 전체 재평가를 진행한다.**
   운영 문항이 정확히 1,300개이고 파일럿의 은행 22건을 재사용한다면 남은 기본 호출은 1,278회다.
   실제 대상 수가 다르면 그 수로 계산하며, 재시도 비용은 기본 호출과 구분한다.
5. 전체 재평가 결과도 별도 영역에 저장한다. 완료 후 다음 자료를 준비하여
   **기존 운영 점수(수동 설정 포함)를 교체하는 사용자 승인을 받는다.**
   재평가 전후 tier별 점수 분포와 이동 현황, 티어·승급 게이트별 표본 약 20문항의
   원문·평가 근거를 제시하여 육안 확인할 수 있게 한다.
6. **파일럿 합격 + 전체 작업 완료 + 최종 실패율 5% 이하 + 운영 교체 승인**을 충족하면
   성공한 결과를 운영 점수로 원자적으로 전환한다.
   실패 문항은 새 평가 결과 영역에 `score=null`, `status="failed"`로 남기고
   기존 운영 점수를 유지한다. 실패를 0점이나 저난도로 해석하지 않는다.

최종 실패율은 전체 재평가 대상 중 최종 실패 문항의 비율로 보고한다.
아직 대기·진행 중인 문항이 있으면 전체 작업 완료로 보고하지 않는다.
이미 승인된 동일한 비용·실행 범위 또는 운영 전환을 다시 승인받을 필요는 없다.

**큐와 실패 처리**

- 백그라운드/큐 방식으로 처리하고 AI API의 레이트 리밋을 준수한다.
- 문항별 실패는 원인을 기록하고 다른 문항 처리를 계속한다.
- 일시적 API 실패 등 재시도 대상 기술 오류는 최대 3회까지 재시도한다.
  기본 평가 호출과 재시도 호출을 구분하여 기록한다.
- 인증·모델 설정 등 공통 장애가 발생하면 전체 작업을 일시 정지한다.
- 허용 경로가 없거나 유효한 평가를 얻지 못했을 때의 결과는 Part 2 §13~§15를 따른다.
  실패를 숨기기 위해 임의 점수를 넣거나 무제한 재호출하지 않는다.

**버전 관리와 재사용**

- AI 원시 판정값(C/R/B/H/E, 경로 구조, 게이트 및 근거)과 스코어러 버전을 분리 저장한다.
- 축·게이트의 판정 정의와 평가 입력이 그대로이고 계산 상수만 바뀌면,
  승인된 변경 범위에서 원시 판정값을 사용하여 AI 재호출 없이 재계산한다.
- `spec_version="1.2"`는 표시용이다. 실제 결과에는 `spec_revision` 또는 평가 입력 해시,
  실제 프롬프트 본문의 SHA-256인 `prompt_hash`, 문항 내용 버전과 스코어러 버전을 기록한다.
  모델·설정·교과 범위·풀이 제한 등 실제 평가 입력을 바꾸는 조건도 재사용 여부에 반영한다.
- **동일 내용 + 동일 평가 입력 버전**일 때만 결과를 재사용한다.
  프롬프트가 바뀌면 해시가 바뀌고 이전 결과와 구분돼야 한다.
- 파일럿 30건 중 **은행에 있는 22건**은 기준과 내용이 같으면 전체 실행에서 재사용한다.
  외부 검증 V1–V8은 문제은행에 없으므로 은행 전체 재평가의 재사용 대상이 아니다.
- 중단 후 재개 시 완료된 문항을 건너뛰고 이어서 실행하여 중복 호출을 방지한다.
- 평가 도중 문항이 수정되면 이전 내용의 결과로 최신 문항의 점수를 덮어쓰지 않는다.
  결과 반영 시 평가 대상 문항 버전과 현재 버전을 확인한다.

### 2.4. 수동 평가 검증 세트 및 파일럿 합격 기준

파일럿은 **외부 검증 8문항(V1–V8) + 문제은행 22문항**, 총 30문항으로 구성한다.

**버전 식별**은 §2.3의 `spec_revision` 또는 평가 입력 해시와 `prompt_hash`를 따른다.
파일럿 결과에 실제 적용한 기준·프롬프트·문항 버전을 함께 기록한다.

**외부 검증 8문항**은 아래 표의 **기대 티어 일치**, 핵심 게이트 발동,
교육과정·풀이 제한 준수를 확인한다. **±1.0은 원인 분석 기준이며 합격 조건이 아니다.**
수동 점수는 티어 안의 대표값이므로 정확한 소수점 일치를 요구하지 않는다.
예상 티어·게이트·풀이 제한에 미해결 불일치가 남아 있으면 합격으로 처리하지 않는다.

**은행 22문항**에는 별도 수동 목표 점수를 부여하지 않는다.
기준 설계에 사용하지 않은 문항을 포함하고, 다음 항목을 확인한다.

- 쉬운 문자식 문항 등에서 문해력 게이트가 불필요하게 발동하지 않는지 확인한다.
- 줄바꿈만 다른 동일 문제는 의미를 바꾸지 않는 입력 정규화 후 해시가 같고
  동일 입력으로 처리되는지 코드로 확인한다. 이 확인만을 위해 AI 호출을 추가하지 않는다.
- 독립 선지의 개수를 합쳐 조립 게이트가 발동하지 않는지 확인한다.
- 의존 사슬 문항은 Part 2 §7·§15의 사슬 조건과 계산 결과가 일치하는지 확인한다.
- 발동 게이트 목록과 짧은 근거를 보고하여 선생님이 직접 확인할 수 있게 한다.

**파일럿 합격**은 외부 8문항의 기대 티어·게이트·풀이 제한과 은행 22문항의 위 검증 항목에
미해결 불일치가 없고, 평가 실패나 스코프 위반이 남아 있지 않은 경우로 한다.
해결되지 않은 기준 충돌이 있으면 전체 실행으로 넘어가지 않는다.

|---|---|---|---|---|
| V1 | 20번 (이등변+외심·내심, 넓이조건) | 9.8 | T5 | 병목 M5 (공통 높이로 넓이→길이, C3R3B3H3 — 4/4 충족. 사용자 확인: 힌트 줘도 어려움) |
| V2 | 21번 (평행사변형+정사각형 2개) | 8.9 | T4 | 병목 M3 (△FAH≅△ABC) + G_assembly |
| V3 | 서답형1 (외심·내심, AC=20) | 9.5+ | T5 | 피타고라스 없이 평가. 쓰면 6.8. "9.5+"는 T5 등급을 의미 (정확히 9.5가 아니라 9.5 이상) |

| V8 | 서술형6 (유한소수, 110/230) | 4.7 | T2 | 병목 M2 (유한소수 판정) |

V3의 `9.5+`는 **T5(9.5~10.0)**를 뜻한다. V3는 피타고라스 정리를 사용하지 않는
허용 경로로 평가하고, V6는 모듈러 연산을 사용하지 않는 허용 경로로 평가한다.
점수만 맞더라도 풀이 제한을 위반하면 통과로 처리하지 않는다.

모델 판정값으로 스코어러가 계산한 점수와 수동 기준을 비교하여 차이를 보고한다.
다음 중 하나라도 해당하면 C/R/B/H, 경로 선택, 게이트 발동 등을 근거로 원인을 분석한다.

- 수동 대표값과 점수 차이의 절댓값이 1.0 이상인 경우.
  V3는 정확한 소수점 목표가 없는 범위 목표이므로 T5 충족 여부로 보고한다.
- 기대 티어가 다른 경우(예: V1의 기대 T5가 T4로 나옴).
- 핵심 승급 게이트의 발동 여부가 다른 경우.
- 허용 교육과정이나 풀이 제한을 위반한 경우.

**검증 문항의 목표 점수·티어·기대 축값을 AI 입력에 넣지 않는다.**
AI는 원문, 대상 문항 지정, 승인된 기준 학생·교과 범위·풀이 제한과 공통 프롬프트로
독립 판정하며, 위 표는 결과 비교에만 사용한다.

원문과 개별 문항이 정확히 매핑된 입력이 있으면 사용할 수 있다.
한 번의 호출로 여러 문항을 묶어 평가하지 않는다.

# Part 2. 평가 기준과 구현 명세 v1.2

이 절에는 기준 학생, 축 정의, 경로 선택, 승급, 점수 공식, 데이터 계약, 기준 코드와 검증 조건을 모두 포함한다. 구현에 필요한 평가 규칙은 이 통합본을 따른다.


## 0. 개요

- 목표: 중등·고등 수학 문항을 해당 과정의 기준 학생에 맞춰 1.0~10.0점으로 평가한다.
- 측정 대상은 발상 병목 난이도를 기본으로 하되, 문제 이해 부하와 실행 부하도 반영하는 **복합 난이도**다.
- 최종 점수와 함께 `base_tier`와 `promotions`를 저장·표시한다. T5에는 단일 발상벽, 의존 사슬, 게이트 승급으로 도달한 경우가 모두 있을 수 있다.
- 핵심 원칙: **난이도는 정답 풀이를 읽었을 때의 복잡함이 아니라, 정답을 모르는 상태에서 핵심 전환을 발견하기 어려운 정도를 중심으로 평가한다.**
- 짧은 풀이가 항상 쉬운 것은 아니고, 긴 풀이가 항상 어려운 것도 아니다. 개념 수·선지 수·계산 단계 수를 발상 수와 동일하게 취급하지 않는다.
- 이번 구현에서는 아래 축 정의, 임계값, 승급 폭, 점수 계수를 고정한다. 파일럿 목표에 맞추기 위한 임의 변경은 하지 않는다.

## 기준 학생 (너가 평가해야 할 대상)

이 학생을 기준으로 난이도를 판단한다. **너(GPT)의 기준이 아니다.**

**이 학생은:**
- 해당 과정의 정의·공식·정리·대표 유형을 완전히 암기하고 이해했다.
- 표준 계산과 대수 조작은 실수 없이 한다.

**하지만 이 학생은:**
- **"아는 것"과 "떠올리는 것"이 다르다.** 피타고라스 정리를 안다고 해서,
  이 문제에서 피타고라스를 써야겠다고 떠올리지는 못한다.
  보조선의 존재를 안다고 해서, 이 도형에 어떤 보조선을 그어야 할지 떠올리지는 못한다.
- **새로운 관점으로 전환하지 못한다.** 넓이 조건이 주어졌을 때 "선분비로 바꿔볼까?"라는
  생각을 하지 못한다. 문자식 답을 보면 "숫자로 안 나오네?" 하고 당황한다.
- **막히면 멈춘다.** 한 접근이 안 되면 다른 접근을 시도하기보다 같은 곳을 맴돈다.
  "다른 모델로 재구성해볼까?" 같은 메타적 사고를 하지 않는다.
- **문제문을 있는 그대로 읽는다.** "△ABR=25"를 보면 넓이인지 각도인지 헷갈려한다.
  복잡한 서술을 만나면 앞에서 읽은 조건을 잊어버린다.
- **경시대회 테크닉은 모른다.** 문제는 처음 보는 상태다. 힌트는 없다.

**절대 하지 말아야 할 판단:**
- "이건 표준 적용이니까 쉽지" — 네가 보기에 표준이어도, 학생에게는 아니다.
  학생이 그 "표준"을 이 문제에 적용해야겠다고 떠올리는 것 자체가 발상이다.
- "다른 쉬운 풀이가 있으니까 쉽지" — 그 쉬운 풀이를 학생이 찾을 수 있느냐가 관건이다.
  네가 찾은 쉬운 길은 학생의 길이 아니다.
- "계산만 하면 되니까 쉽지" — 계산 과정이 길고 복잡하면 학생은 실수하고 지친다.
  실행 부하도 난이도다.

**판정 원칙:**
의심스러우면 어렵게 판정한다. C/R/B를 매길 때 "이 정도면 학생이 떠올릴까?"라고
자문하고, 확신이 없으면 한 단계 높게 준다. 쉽게 주는 것보다 어렵게 주는 쪽이
실제 교실 관찰에 가깝다.

## 2. 교과과정 범위 고정 (Strict Curriculum Scope Lock)

- 평가 범위는 **문항이 속한 과정에 따라 결정**된다.
  중등 문항이면 중등 과정, 고등 문항이면 고등 과정이 기준이다.
  (문제은행에는 고등 과정 시험지도 올라오므로, 중등으로만 한정하지 않는다.)
- 금지: **해당 수준을 벗어난 상위 교육과정 도구**로 발상을 우회하는 풀이.
  - 예: 중등 도형 문항에서 좌표평면을 도입해 기하학적 통찰을 우회하는 풀이는 제외.
    (단, 좌표 자체가 문제의 주제이거나 우회가 아닌 경우는 허용.
    "좌표 사용"이라는 넓은 분류로 일괄 금지하지 않고, 실제 사용된 개념이
    허용 범위를 벗어나 핵심 발상을 우회하는지 개별 판단한다.)
  - 예: 고등 삼각함수(배각공식·사인법칙 등)를 중등 문항에 사용하는 것은 금지.
  - 예: 고등 문항에서는 그 수준을 벗어난 대학 과정 도구 사용 금지.
- 절차: 반드시 해당 수준의 도구만으로 된
  **학생 기준 정석 풀이(canonical student solution)** 를 먼저 구성한 뒤,
  그 풀이의 발상 난도를 평가한다.
- `curriculum_scope` 필드에 문항의 과정 수준을 기록한다 (예: `"중2"`, `"고1"`).

- **강력한 도구에 대한 처리 (금지가 아님 — 출제 의도 보존)**:
  피타고라스 정리·모듈러 연산 등 강력한 도구를 사용하지 않고도 풀 수 있다면,
  그 풀이를 기준으로 점수를 매긴다. 이는 해당 도구를 "금지"하는 것이 아니라,
  **문제가 의도한 핵심 발상을 평가하기 위해** 우회 경로를 제외하는 것이다.
  - 적용 범위: 해당 도구를 사용하면 문제의 핵심 통찰을 우회하게 되는 경우.
    (예: 서답형1은 피타고라스를 쓰면 내심·외심의 관계 파악이라는 핵심을 건너뛰게 됨.)
  - 적용하지 않는 경우: 도구 없이 푸는 것이 불가능하거나 비현실적인 경우,
    또는 도구를 써도 핵심 발상이 그대로 필요한 경우에는 도구 사용 풀이로 평가해도 된다.
  - 최종 점수의 의미: "출제 의도상 허용된 풀이 중 가장 쉬운 경로의 난이도".
    즉, 특정 발상을 평가하려는 문제에서는 그 발상을 우회하는 도구를 제외한 상태에서의 난이도다.
  - 좌표 사용 여부 같은 넓은 분류로 일괄 금지하지 않는다.
    실제 풀이에 사용된 개념이 허용 범위에 속하는지 개별 판단한다.
  (V3의 검증 목표는 피타고라스 우회 경로를 제외했을 때 T5이며, 소수점의 정확한 일치를 요구하지 않는다.)
- **중요**: 강력한 도구 없이 풀 수 있는 문제는, 강력한 도구를 사용한 우회 경로를
  `viable_routes`에 포함하지 않는다.
  (min-over-paths가 저절로 쉬운 쪽을 선택해 버리는 것을 방지.
  예: 서답형1에서 피타고라스 사용 경로(6.8)를 제외하고 미사용 경로(9.5)만 평가.)
  부득이 포함해야 한다면 각 route에 `uses_powerful_tool: true` 플래그를 달고,
  §15 스코어러는 이 플래그가 있는 route를 min-over-paths 대상에서 제외한다.

- `uses_powerful_tool=true`는 이 절에 따라 제외할 우회 경로임을 표시한다. 도구를 사용해도 허용되는 예외 경로까지 일괄 제외하는 의미가 아니다. 필터링 후 허용 경로가 하나도 남지 않으면 §13에 따라 채점 실패로 처리한다.

## 3. 임계 발견 (critical_discovery)

- 정의: **현재까지 얻은 정보만으로 다음 행동이 거의 강제되지 않으며,
  여러 가능한 행동 중 특정 구조·관계·표현을 새로 선택해야만 풀이가 의미 있게 진전되는 전환.**
- 다음은 임계 발견으로 세지 않는다:
  - 정의의 직접 사용
  - 문제가 사실상 직접 호출하는 공식 대입
  - 앞 단계에서 자동으로 따라오는 계산
  - 같은 발상을 여러 선지에 반복 적용
  - 산술/대수 조작 낱개

- **발견 쪼개기 규칙** (§7b 조립 게이트 판정용):
  하나의 정리·사실로 한 번에 해결되는 단위를 하나의 발견으로 센다.
  같은 정리·사실의 단순 반복 적용은 하나로 합친다.
  계획을 세우는 것과 실행하는 것은 **새로운 비자동적 선택이 필요할 때만**
  별개의 발견으로 센다. 발견 이후 자동으로 이어지는 실행
  (예: 보조선을 떠올린 뒤 실제로 긋는 것, 닮음을 발견한 뒤 바로 닮음비를 계산하는 것)은
  같은 발견에 포함한다. 오직 새로운 판단·선택이 필요한 지점만 분리한다.

- 의존 그래프를 표현하기 위해 루틴·자동 중간 단계를 기록할 수 있다. 이런 단계는 실제 의존 연결을 보존하는 데 사용하되, 비자동적 발견을 세는 사슬·조립 조건의 개수에는 포함하지 않는다.

## 4. 평가 3축 + H (0~4점)

각 축은 아래 고정 메뉴에서 선택한다 (자유 서술 금지).

| 축 | 0점 | 1점 | 2점 | 3점 | 4점 |
|---|---|---|---|---|---|
| **C: 단서 희박성** | 사용할 방법이 사실상 직접 명시됨 | 전형적 키워드/배치가 즉시 촉발 | 간접적이지만 가까운 단서가 있음 | 단서가 약하거나 여러 조건에 흩어져 있음 | 직접 단서가 거의 없거나 표면이 다른 방향으로 유도 |
| **R: 표현 전환** | 직접 공식 대입/정의 사용 | 익숙한 두 사실의 표준 결합 | 명시되지 않은 관계를 찾아야 함 | 보조구조·재해석·숨은 도형 관계 도입 | 문제를 다른 모델·표현·불변량으로 재구성 |
| **B: 탐색 분기·막힘** | 다음 단계가 사실상 강제 | 1~2개의 매우 표준적인 후보 | 여러 정상 후보가 있으나 진행 신호 있음 | 여러 그럴듯한 접근이 있고 피드백이 약함 | 자연스러운 접근이 막히고 관점 전환/재출발 필요 |
| **H: 힌트 붕괴도** (게이트 전용) | 알려줘도 거의 안 쉬워짐 | 조금 쉬워짐 | 난점의 상당 부분 제거 | 주요 난점 대부분 제거 | 알려주면 이후가 거의 루틴 |

## 5. 루틴 게이트 (Routine Gate)

- `C ≤ 1 AND R ≤ 1 AND B ≤ 1` 이면 H가 아무리 높아도 **M0(루틴)** 으로 분류한다.
- "공식을 알려주면 문제가 끝난다"는 이유만으로 직접 공식 적용 문제를 고난도로 오판하는 것을 막는다.

## 6. Move 분류 (M0~M5)

다음 순서로 판정한다. C/R/B/H는 각각 0~4 정수다.

1. `C≤1 AND R≤1 AND B≤1`이면 H와 무관하게 **M0**.
2. `R≥3 AND C≥3 AND B≥2 AND H≥3` 네 조건을 모두 충족하면 **M5**.
3. 그 외에는 `A=C+R+B`로 분류한다. H는 A에 넣지 않는다.

| 조건 | Move |
|---|---|
| A≥8 | M4 |
| 6≤A<8 | M3 |
| 4≤A<6 | M2 |
| 나머지 | M1 |

이 임계값과 판정 순서를 이번 구현에 고정한다. V1의 고정 검증 축 C3/R3/B3/H3은 M5 조건 네 개를 모두 충족한다.

## 7. 경로 등급 (Path Tier)

### 7a. 기본 tier 결정

한 풀이 가지에서 다음 순서로 판정한다.

1. M5가 하나라도 있으면 **T5**.
2. 의존 사슬 안의 비자동적 M4가 2개 이상이면 **T5**.
3. 의존 사슬 안의 비자동적 M3 이상 발견이 3개 이상이면 **T5**.
4. 그 외에는 가장 높은 Move를 기본 tier로 사용한다: M4→T4, M3→T3, M2→T2, M1→T1, M0→T0.

“의존한다”는 앞의 구조나 결과를 얻기 전에는 다음 발상의 필요성을 정상적으로 인식하기 어려운 관계를 뜻한다. 사슬의 구성원은 `is_non_obvious=true`인 대상 Move만 센다. 대상 Move가 아닌 중간 단계도 원래 그래프에서 연결을 이어 주면 보존한다. 예를 들어 M4→M0→M4는 대상 M4 두 개의 의존 사슬이 될 수 있다.

동일한 종류의 사슬 후보에서는 **길이가 긴 순서 → S 평균이 높은 순서 → 발견 ID의 고정된 순서**로 하나를 선택한다. 위 1~3번의 판정 우선순위는 유지한다. 사슬 평균에는 선택된 구성원만 포함하며, 무관한 발견은 포함하지 않는다.

### 7b. 승급 게이트

기본 tier를 결정한 뒤 각 게이트를 확인한다. 발동한 게이트의 승급 폭을 합산하며, 최종 tier의 상한은 T5다.

- **G_assembly (조립 부하, +1)**: 동일한 풀이 가지 안에서 실제로 연결된 **M2 이상이고 `is_non_obvious=true`인 발견이 3개 이상**이면 발동한다.
  - 연결 여부는 해당 가지의 원래 `depends_on` 그래프 전체로 판단한다. M0·M1 또는 자동적인 중간 노드도 실제 의존 연결에는 남겨 둔다.
  - 개수에는 비자동적 M2 이상 발견만 포함한다. `is_non_obvious=false`인 발견은 Move와 무관하게 개수에서 제외한다.
  - 따라서 M2→M0→M2→M1→M2도 비자동적 M2 세 개가 실제로 이어져 있으면 발동한다.
  - 서로 독립인 선지·가지·무관한 소문항의 발견을 합쳐 개수를 채우지 않는다.
  - 객관식 병렬 선지는 하나의 route의 `independent_branches`로 기록하고 가지별로 평가한다. 코드가 가장 어려운 가지를 선택한다. 여러 선지를 확인하는 수고는 실행량 E에 반영한다.
  - 독립 소문항은 가지를 분리한다. 실제로 의존하는 소문항은 해당 의존 흐름을 같은 그래프에 `depends_on`으로 명시한다.
  - 하나의 정리·사실을 잘게 쪼개거나 반복 적용한 것을 여러 비자동적 발견으로 세지 않는다(§3).
- **G_literacy (문해력 부하, +2)**: HIGH 문해력 부하가 있으면 +2.
  (요즘 학생들이 풀이보다 "문제가 이해 안 된다"고 질문하는 경우가 늘어남.
  문해력 부하를 +2로 상향. 단, 아래 기준을 엄격히 적용한다.)
  **경계 원칙**: 서술을 수학적으로 해석하는 과정에 새로운 관계나 모델의
  *발견*이 필요하다면, 그것은 C/R/B의 영역이지 G_literacy가 아니다.
  G_literacy는 순수한 언어적·기억적 부하(파싱, 작업 기억)에만 적용한다.
  수학적 통찰이 필요한 해석은 C/R/B에 반영하고, G_literacy와 중복 계산하지 않는다.

  (a) 파싱: 비표준적이거나 길고 복잡한 서술을 수학적 구조로 옮기는 데
  상당한 노력이 필요함. 단, 그 과정에서 새로운 수학적 관계를 *발견*해야 한다면
  C/R/B로 분류한다. G_literacy(a)는 발견 없이도 정리 자체가 버거운 경우에만 해당.
  (예: 1501의 비표준 주사위 게임 규칙.)
  (b) 문자식 매칭: 답을 문자로 된 식으로 정리해서 선지와 매칭해야 하고,
  그 정리에 자명하지 않은 변형이 필요함. 단순한 공식 대입으로 나오는 문자식은 제외.
  (예: 1425의 EG+FH — 숫자가 아닌 식으로 정리하는 과정에서 막힘.)
  (c) 작업 기억 과부하: 한 번에 유지해야 할 독립 조건이 많아서 앞에서 읽은 내용을
  잊어버릴 정도임. 단순히 "4줄 초과"나 "조건 4개"가 아니라,
  실제로 이해를 방해하는 수준의 과부하가 있어야 함.
  (줄 수는 글꼴·지면 폭에 따라 달라지므로, 절대적 기준으로 사용하지 않는다.
  조건의 *상호 의존성*과 *비표준성*을 함께 고려한다.)
  (a)(b)(c) 중 하나라도 해당하면 발동. 경계선에서는 발동하지 않음 (보수적).
- **G_execution (실행 부하, +1)**: EXTREME 실행 부하가 있으면 +1.
  경우 세기·계산이 매우 길고 실수 유발 가능성이 높아서,
  꼼꼼한 실행 자체가 주요 난이도인 경우 (예: 1500의 중복 숫자 처리).

- C/R/B는 **문제를 정확히 이해했다는 전제 하의 수학적 발견 난이도**만 평가한다.
  서술 파싱 자체의 어려움은 G_literacy로만 반영하고, C에 중복 반영하지 않는다.
- G_literacy와 G_execution은 AI가 §14 JSON의 `literacy_high`,
  `execution_extreme` 불리언으로 판정한다.
  판정 기준: 보통 문제에서는 false. 위 (a)(b)(c)나 EXTREME 실행에 해당하는
  명백한 경우에만 true. 경계선에서는 false를 유지한다 (보수적 판정).
- 승급 후 소수점 재계산은 §11 규칙을 따른다
  (새 밴드에서 병목 발견의 S로 계산, 승급으로 하한 근처에 몰리지 않게).

- `promotions`는 발동한 게이트 목록이다. 기본 tier가 이미 T5인 경우에도 모든 게이트를 확인해 기록한다. T5 상한 때문에 실제 tier가 더 높아지지 않을 수 있으며, `base_tier="T5"`와 기존 T5 점수 공식을 유지한다. 단일 M5·사슬 판정에서 필수 메타데이터를 생략하는 조기 반환을 하지 않는다.

## 8. 문제 등급 = min over viable paths

- 문제 난이도는 **출제 의도상 허용되고 현실적으로 가능한 정규교과 풀이들 중 가장 쉬운 경로**를 기준으로 한다.
  - 어려운 기발한 풀이가 있다는 이유로 쉬운 문제가 고난도가 되어서는 안 된다.
- **viable에서 제외**: 수십 개 경우를 전개하는 비현실적 brute force,
  교육과정 밖 고급 정리, 학생이 정상적으로 선택하기 어려운 과도한 계산 우회법.
- 참고 예시 (1484번): 평행사변형 인식 루트와
  각의 이등분선 정리+닮음으로 AR=3을 도출하는 루트 둘 다 viable —
  둘 중 쉬운 쪽으로 평가한다.

- 허용된 대체 경로는 최종 `(tier, score)`가 낮은 것을 선택한다. 티어가 같으면 소수점 점수가 낮은 경로를 선택한다. 배열의 입력 순서가 점수에 영향을 주지 않아야 한다.
- 허용 경로가 없으면 점수를 만들지 않고 §13의 실패 처리로 넘긴다.

## 9. 병렬 분기 Max-Pooling

- 객관식의 독립 선지나 독립 소문항은 하나의 route 안의 `independent_branches`에 기록한다. 각 가지의 발견 목록은 별도로 유지한다.
- 코드가 각 가지의 최종 `(tier, score)`를 계산한 뒤 가장 높은 결과를 선택한다. 독립 가지를 여러 대체 route로 만들어 min 선택에 넣지 않는다.
- 여러 선지를 확인하는 수고는 route의 실행량 E에 반영한다. 가지에 실행량을 별도로 제공하는 경우에도 전체 확인 부담을 반영하며, 생략하면 route의 E를 사용한다.
- 한 선지 안에서 필요한 보조선·불변량·표현 전환은 그 가지의 발견으로 평가한다. 서로 다른 독립 가지의 발견 수는 합치지 않는다.
- 단일 가지 route는 `critical_discoveries`를 사용하고 `independent_branches=[]`로 둔다. 여러 독립 가지를 기록한 route는 route 수준 `critical_discoveries=[]`로 두어 중복 집계하지 않는다.

## 10. 티어 구간

| 티어 | 점수 | 의미 |
|---|---|---|
| T0 | 1.0–2.0 | 정의·공식·대표 성질이 거의 직접 호출됨 |
| T1 | 2.1–3.8 | 몇 개의 뻔한 표준 방법 중 하나를 고르면 됨 |
| T2 | 3.9–5.8 | 알려진 사실을 한 번 비직접적으로 연결 (구조는 비교적 잘 보임) |
| T3 | 5.9–7.7 | 말하지 않은 관계나 보조구조를 스스로 발견해야 함 |
| T4 | 7.8–9.4 | 단서가 약하고 정상 탐색이 쉽게 진전되지 않으며 핵심 힌트가 난이도를 크게 붕괴시킴 |
| T5 | 9.5–10.0 | 단일 발상벽·강한 발상의 의존 사슬 또는 승급 게이트로 도달한 최고 등급 |

- **절대로 단순 가중합 하나로 처음부터 1~10을 계산하지 않는다.
  먼저 tier를 결정하고, 그 다음 tier 내부 소수점을 결정한다.**

## 11. 소수점 계산 (이번 구현의 고정 상수)

- 임계 발견의 심각도: `S = (0.40·C + 0.35·R + 0.25·B) / 4` (H는 제외 — H는 게이트용)
- 실행량 `E` (0~4, 별도 평가. **티어를 올릴 수 없고 같은 티어 안에서만 반영**):
  - 0: 계산 거의 없음 / 1: 1~2회 단순 실행 / 2: 몇 단계 표준 계산 /
    3: 여러 계산 또는 여러 선지 확인 / 4: 긴 실행이지만 시험에서 현실적
- `T0`: `score = min(2.0, 1.0 + 0.6·S + 0.1·E)`
- `T1~T4`: tier 하한=L, 상한=U에 대해
  `score = L + (U−L) × (0.85·S + 0.15·(E/4))`, 해당 tier 범위로 clamp
- `T5 single-wall`: `score = 9.5 + 0.4·S`
- `T5 chain`: 사슬을 구성하는 주요 발견들의 S 평균을 사용,
  `score = 9.5 + 0.4·S_avg + 0.1`
- 승급 게이트(§7b)로 승급한 경우, 승급한 tier의 밴드에서
  병목 발견의 S로 소수점을 다시 계산한다.
  (승급한 티어의 하한 근처에 점수가 몰리지 않게 하기 위함.)
- 최종값은 10.0 이하로 clamp, 0.1 단위 반올림.
- 이 가중치·계수·상수는 추후 실측으로 보정할 수 있는 설계값이지만, 이번 구현에서는 고정한다. 변경이 필요하면 파일럿 결과와 이유를 보고하고 사용자 승인을 받는다.
- 게이트 승급으로 T5에 도달했고 기본 판정이 의존 사슬 T5가 아니면 `9.5 + 0.4·S`를 사용한다. 사슬 보너스 `+0.1`은 실제 선택 사슬로 기본 T5가 된 경우에만 적용한다.

## 12. 판정 절차 (기본: 단일 호출)

모델에게 처음부터 "몇 점?"이라고 묻지 않는다. 아래 순서로 강제한다.

- **PASS A — 풀이 전 단서 판독** (점수 없음):
  문제에 직접 제시된 개념/정리, 기준 학생에게 즉시 떠오를 표준 접근,
  문제 표면이 특정 방법을 얼마나 암시하는지, 표준 접근이 막힐 지점,
  명시되지 않은 보조선/표현/모델이 필요할 가능성.
- **PASS B — 풀이 경로 탐색**: 문제를 정확히 풀고, 정규교과 내 현실적 경로 2~4개를 검토한다. 실제 확인한 허용 경로만 반환한다.
  장문의 chain-of-thought가 아니라 `route_summary` + `critical_discoveries` 목록만 반환.
  **단, §2의 강력한 도구 규칙에 따라 강력한 도구 없이 풀 수 있는 문제는
  강력한 도구를 사용한 우회 경로를 viable_routes에 포함하지 않는다.**
  (포함이 불가피하면 `uses_powerful_tool: true` 플래그를 단다.)
- **PASS C — 병목 판정**: A의 사전 단서와 B의 실제 발견을 비교해 C/R/B/H와 짧은 근거, 실행량, 게이트 조건을 판정한다.
  Move·경로 tier·문제 tier·최종 점수는 반환 이후 §15 코드가 계산한다.

- **기본 모드: 1회 API 호출**, 프롬프트 내 섹션 순서(A→B→C) 강제.
  (비용 기준: 문제당 기본 1회 호출을 원칙으로 한다.)
- `strict_calibration=true` 일 때만 패스별 분리 호출.
- 주의: PASS B를 본 뒤 PASS A의 단서를 소급해서 상향하지 않는다
  ("정답을 알고 나니 보이는 단서"는 단서가 아니다).

## 13. 채점할 수 없는 문항과 실패 처리

- 경로 목록 자체가 비어 있으면 `(None, None, {"reason": "no_routes"})`를 반환한다.
- §2의 경로 제외 조건을 적용한 뒤 허용 경로가 남지 않으면 `(None, None, {"reason": "no_eligible_routes"})`를 반환한다.
- 제외된 경로를 되살려 점수를 계산하지 않는다. 허용 풀이를 확보하지 못했다는 사실을 기록한다.
- 새 평가 결과는 `tier=null`, `score=null`, `status="failed"`로 저장하고 사유를 남긴다. 풀이를 확보하지 못한 경우의 결과 신뢰도는 0으로 처리한다.
- 허용 경로 미확보도 실패율에 포함하며 기존 운영 점수는 유지한다. 실패를 0점·저난도·성공한 fallback으로 처리하지 않는다.
- 스키마 검증 실패나 스코어러 입력 오류도 문항별 실패로 기록한다. 필수 값 누락을 임의의 쉬운 점수로 저장하지 않는다.
- 일시적 API 장애만 Part 1의 제한 내에서 재시도한다. 풀이 미확보·기준 불일치 때문에 추가 유료 평가를 자동 반복하지 않는다. 인증·모델 설정 같은 공통 장애는 전체 작업을 일시 정지한다.

모델은 최종 점수를 직접 쓰지 않는다. 아래 구조까지만 판정하고,

**역할 분리**: AI는 위 JSON에서 다음만 채운다 —
C/R/B/H (0-4 정수), E (`execution_load`, 경로별), `execution_extreme` (경로별),
`critical_discoveries`의
원시 필드, `literacy_high`/`execution_extreme` 불리언과 그 근거.
**`literacy_high=true`일 때는 `literacy_evidence`에 문제문의 해당 부분을 인용해야 하며,
`execution_extreme=true`일 때는 `execution_evidence`에 실행량이 극단적인 이유를
구체적으로 기록해야 한다. 근거 없이 true로 두면 파일럿에서 반려된다.**
다음 계산 필드는 AI 출력 스키마에서 제외하고 코드가 §15로 계산한다:
`move_class`, `base_tier`, `path_tier`, `problem_tier`, `promotions`, `score`, `is_easiest`,
`single_insight_wall`. AI가 실수로 채워도 코드는 무시하고 재계산한다.

- `clue_in_text` (discovery별): 원문에 실제로 제시된 단서를 짧게 기록.
- `must_construct` (discovery별): 학생이 스스로 만들어야 하는 관계·구조를 짧게 기록.
- `hint_effect` (discovery별): 핵심 힌트가 제거하는 어려움을 짧게 기록.
  (장문의 사고 과정 불필요. 판정 근거만.)

- `literacy_high`: G_literacy 판정 (§7b). HIGH 문해력 부하가 있으면 true.
  (a) 비표준적이거나 길고 복잡한 서술을 수학적 구조로 옮기는 데 상당한 노력이 필요하거나
  (단, 새로운 수학적 관계의 발견이 필요하면 C/R/B로 분류),
  (b) 답을 문자로 된 식으로 정리해서 선지와 매칭해야 하고 그 정리에 자명하지 않은 변형이 필요하거나,
  (c) 한 번에 유지해야 할 독립 조건이 많아 실제로 이해를 방해하는 수준의 작업 기억 과부하가 있는 경우.
  (단순 "4줄 초과"나 "조건 4개"는 절대 기준으로 사용하지 않음. §7b 참조.)
  (a)(b)(c) 중 하나라도 해당하면 true.
  보통 문제는 false. 경계선에서는 false (보수적 판정).
- `execution_extreme`: G_execution 판정 (§7b). 경우 세기·계산이 매우 길고
  실수 유발 가능성이 높아서 꼼꼼한 실행 자체가 주요 난이도이면 true.
  보통 문제는 false. 경계선에서는 false (보수적 판정).
- `uses_powerful_tool` (route별): 해당 경로가 피타고라스 정리·모듈러 연산 등
  강력한 도구를 사용하는 우회 경로이면 true. §2 규칙에 따라 강력한 도구 없이
  풀 수 있는 문제는 이런 경로를 viable_routes에 포함하지 않는 것이 원칙이나,
  부득이 포함된 경우 스코어러가 min-over-paths에서 제외한다.
- `parallel_branch_count` (route별): 객관식에서 병렬로 시도 가능한 가지 수.
  1보다 크면 §9 max-pooling 적용 여부를 판단하는 근거가 된다.
- `is_non_obvious` (discovery별): 앞 발견이 다음 발견을 자동으로 알려주는 관계가
  아닐 때 true. 즉, 이 발견은 앞 단계에서 자연스럽게 도출되지 않고 별도의
  통찰이 필요함을 의미한다. 사슬 길이 판정(§7a) 시 의존 관계의 강도를 판단하는
  보조 지표로 사용한다. `is_non_obvious: false`인 발견은 사슬 길이와 조립 승급 개수에 포함하지 않는다. 실제 의존 연결을 이어 주는 역할은 유지한다.
- `id` / `depends_on` (discovery별): 발견의 고유 ID와, 이 발견이 의존하는
  앞 발견들의 ID 목록. `depends_on: []`이면 사슬의 시작점.
  ID 기반 그래프로 실제 연결된 사슬의 길이를 계산한다.
  예: `{"id": "d1", "depends_on": []}`, `{"id": "d2", "depends_on": ["d1"]}`.
- `promotions`: 발동한 승급 게이트 목록. 스코어러가 채움
  (예: `["assembly"]`, `["assembly", "execution"]`).
- `confidence`: 평가 근거를 얼마나 안정적으로 확보했는지 (학생 정답 확률이 아님).
- `parallel_branch_count`가 1보다 크면(객관식 병렬 가지) §9 max-pooling 적용 여부를
  `multiple_choice_execution_only`와 함께 기록한다.

### 14a. 독립 가지의 구조

`independent_branches`가 비어 있지 않으면 각 항목은 다음 필드를 갖는다.

| 필드 | 의미 |
|---|---|
| `branch_id` | route 안에서 고유한 안정적인 가지 ID |
| `critical_discoveries` | 위와 같은 발견 객체의 배열. 의존 ID는 같은 가지 안에서 해석 |
| `execution_load` | 선택 필드. 있으면 0~4 정수이며 없으면 route의 E 사용 |

route 수준 `execution_extreme`은 해당 route의 모든 가지 평가에 공통 적용한다. 다른 대체 route로 전파하지 않는다. 독립 가지 사이에는 가짜 의존 연결을 만들지 않는다.

위 JSON은 데이터 구조 예시다. Codex는 이 계약으로 실제 구조화 출력용 JSON Schema를 작성한다. 필수 필드, 축 값과 실행량의 범위, 불리언, 고유 ID, 존재하는 의존 ID, 의존 그래프의 비순환성을 검증한다. 제공된 모델 식별자와 구조화 출력 옵션은 실제 지원 환경에서 확인한다.

### 14b. 코드가 추가하는 성공 결과

| 필드 | 기록 규칙 |
|---|---|
| `problem_tier`, `score` | 스코어러가 선택한 최종 결과 |
| `base_tier` | 게이트 승급 전 기본 tier. 처음부터 T5인 경우에도 T5를 기록 |
| `promotions` | 발동한 게이트 이름 배열. 미발동은 빈 배열, T5 상한에서도 발동 내역 기록 |
| `trigger` | `single_wall`, `dependent_chain`, `bottleneck`, `promoted` 등 기본 판정·승급의 근거 |
| `dominant_s` | 선택한 병목의 S |
| `chain_s_avg` | 실제 선택 사슬의 S 평균. 사슬 판정이 아니면 null |
| `chain_ids` | 실제 선택 사슬 구성원. 사슬 판정이 아니면 빈 배열 |
| `selected_route_id` | 최종 선택한 허용 대체 route ID |

모든 성공 결과는 같은 필드 계약을 따른다. 입력 구조와 표시용 데이터는 별도로 보관하되 AI가 적은 최종 점수가 있더라도 채택하지 않는다. 실패 결과는 §13의 별도 계약을 따른다.

`spec_version="1.2"`와 함께 평가 입력 revision 또는 해시, `prompt_hash`, 모델 설정, 문항 버전, 스코어러 버전을 기록한다. AI 원시 판정값과 코드 계산 결과는 분리해 저장한다.

## 15. 결정론적 스코어러 (Python 기준 코드)

아래 코드는 점수 규칙을 구현한 기준 코드다. Codex는 리포지토리의 언어·모듈·저장 규약에 맞게 옮기고 §17을 검증한다. 함수는 §14 검증을 마친 유효 입력을 받는 것으로 한다. 예외와 실패 결과는 호출 계층에서 문항별로 처리한다.

```python
TIER_BANDS = {
    "T0": (1.0, 2.0), "T1": (2.1, 3.8), "T2": (3.9, 5.8),
    "T3": (5.9, 7.7), "T4": (7.8, 9.4), "T5": (9.5, 10.0),
}
MOVE_TO_TIER = {"M0": "T0", "M1": "T1", "M2": "T2",
                "M3": "T3", "M4": "T4", "M5": "T5"}
TIER_ORDER = ["T0", "T1", "T2", "T3", "T4", "T5"]


def classify_move(c, r, b, h):
    """C/R/B/H (0~4 정수)에서 Move class 계산."""
    for value, name in [(c, "C"), (r, "R"), (b, "B"), (h, "H")]:
        if type(value) is not int or not 0 <= value <= 4:
            raise ValueError(f"{name}는 0~4 정수여야 함: {value}")
    if c <= 1 and r <= 1 and b <= 1:
        return "M0"
    if r >= 3 and c >= 3 and b >= 2 and h >= 3:
        return "M5"
    a = c + r + b
    if a >= 8:
        return "M4"
    if a >= 6:
        return "M3"
    if a >= 4:
        return "M2"
    return "M1"


def severity(c, r, b):
    return (0.40 * c + 0.35 * r + 0.25 * b) / 4.0


def _calc_s(discovery):
    return severity(discovery["C"], discovery["R"], discovery["B"])


def _severity_units(discovery):
    # 기존 S의 80배. 사슬 동률 비교에서 부동소수점 오차만 피한다.
    return 8 * discovery["C"] + 7 * discovery["R"] + 5 * discovery["B"]


def _successors(id_map):
    """전체 depends_on 그래프. 낮은 클래스·자동적인 발견도 연결에 포함."""
    successors = {did: set() for did in id_map}
    for did, discovery in id_map.items():
        for dep_id in discovery["depends_on"]:
            successors[dep_id].add(did)
    return successors


def _max_chain(target_classes, discoveries, id_map):
    """(해당 클래스의 발견 수, 선택된 사슬 ID 목록)을 반환한다.

    선택 순서: 최장 길이 → 높은 S 평균 → 사슬 ID의 사전순.
    중간의 비대상 발견은 연결에는 사용하고 길이·평균에서는 제외한다.
    예: M4→M0→M4는 길이 2의 M4 사슬이다.
    """
    successors = _successors(id_map)
    memo, visiting = {}, set()

    def chain_key(chain):
        # 길이가 같은 사슬끼리는 S 합과 S 평균의 순서가 같다.
        return (-len(chain),
                -sum(_severity_units(id_map[did]) for did in chain),
                tuple(chain))

    def longest_from(did):
        if did in memo:
            return memo[did]
        if did in visiting:
            raise ValueError("depends_on 그래프에 순환이 있음")
        visiting.add(did)
        best_tail = ()
        for nxt_id in sorted(successors[did]):
            candidate = longest_from(nxt_id)
            if chain_key(candidate) < chain_key(best_tail):
                best_tail = candidate
        discovery = id_map[did]
        is_target = (discovery["_move_class"] in target_classes
                     and discovery["is_non_obvious"])
        chain = ((did,) if is_target else ()) + best_tail
        visiting.remove(did)
        memo[did] = chain
        return chain

    best = ()
    for did in sorted(id_map):
        candidate = longest_from(did)
        if chain_key(candidate) < chain_key(best):
            best = candidate
    return len(best), list(best)


def _assembly_triggered(discoveries, id_map):
    """전체 그래프의 연결을 보존하고 비자동적 M2+ 발견만 센다."""
    parent = {did: did for did in id_map}

    def find(did):
        while parent[did] != did:
            parent[did] = parent[parent[did]]
            did = parent[did]
        return did

    def union(first, second):
        first_root, second_root = find(first), find(second)
        if first_root != second_root:
            parent[first_root] = second_root

    # M0/M1/자동 노드도 연결을 끊지 않는다.
    for discovery in discoveries:
        for dep_id in discovery["depends_on"]:
            union(discovery["id"], dep_id)

    counts = {}
    for discovery in discoveries:
        if (int(discovery["_move_class"][1]) >= 2
                and discovery["is_non_obvious"]):
            root = find(discovery["id"])
            counts[root] = counts.get(root, 0) + 1
    return any(count >= 3 for count in counts.values())


def classify_path(discoveries, literacy_high=False, execution_extreme=False):
    """한 풀이 가지를 분류한다. 원시 입력을 바꾸지 않는다.

    입력은 §14의 유효한 스키마를 전제로 한다. ID는 가지 안에서 고유하며,
    depends_on은 같은 가지에 존재하는 ID를 참조한다.
    성공 정보의 공통 필드: trigger, base_tier, promotions,
    dominant_s, chain_s_avg, chain_ids.
    """
    if not discoveries:
        discoveries = [{"id": "synthetic_m0", "C": 0, "R": 0, "B": 0, "H": 0,
                        "depends_on": [], "is_non_obvious": True}]
    evaluated = [dict(discovery,
                      _move_class=classify_move(discovery["C"], discovery["R"],
                                                discovery["B"], discovery["H"]))
                 for discovery in discoveries]
    id_map = {discovery["id"]: discovery for discovery in evaluated}
    top_discovery = min(evaluated,
                        key=lambda d: (-int(d["_move_class"][1]),
                                       -_calc_s(d), d["id"]))
    base_tier = MOVE_TO_TIER[top_discovery["_move_class"]]
    dominant_s = _calc_s(top_discovery)
    trigger, chain_ids, chain_s_avg = "bottleneck", [], None

    # 기본 티어 우선순위: M5 → M4 사슬 → M3+ 사슬 → 단일 병목.
    if top_discovery["_move_class"] == "M5":
        base_tier, trigger = "T5", "single_wall"
    else:
        m4_len, m4_ids = _max_chain({"M4"}, evaluated, id_map)
        if m4_len >= 2:
            base_tier, trigger, chain_ids = "T5", "dependent_chain", m4_ids
        else:
            m3_len, m3_ids = _max_chain({"M3", "M4", "M5"}, evaluated, id_map)
            if m3_len >= 3:
                base_tier, trigger, chain_ids = "T5", "dependent_chain", m3_ids
        if chain_ids:
            chain_values = [_calc_s(id_map[did]) for did in chain_ids]
            chain_s_avg = sum(chain_values) / len(chain_values)
            dominant_s = max(chain_values)

    # 기본 티어가 T5여도 모든 발동 게이트를 기록한다.
    promotions, increase = [], 0
    if _assembly_triggered(evaluated, id_map):
        promotions.append("assembly")
        increase += 1
    if literacy_high:
        promotions.append("literacy")
        increase += 2
    if execution_extreme:
        promotions.append("execution")
        increase += 1
    tier = TIER_ORDER[min(5, TIER_ORDER.index(base_tier) + increase)]
    if trigger == "bottleneck" and promotions:
        trigger = "promoted"
    return tier, {"trigger": trigger, "base_tier": base_tier,
                  "promotions": promotions, "dominant_s": dominant_s,
                  "chain_s_avg": chain_s_avg, "chain_ids": chain_ids}


def decimal_score(tier, s, e=0, s_avg=None):
    lo, hi = TIER_BANDS[tier]
    if tier == "T0":
        return round(min(2.0, 1.0 + 0.6 * s + 0.1 * e), 1)
    if tier == "T5":
        base = 9.5 + 0.4 * (s_avg if s_avg is not None else s)
        if s_avg is not None:
            base += 0.1
        return round(min(10.0, base), 1)
    return round(min(hi, max(lo, lo + (hi - lo)
                            * (0.85 * s + 0.15 * (e / 4.0)))), 1)


def score_problem(viable_routes, literacy_high=False):
    """완전한 대체 풀이에는 min, 한 풀이의 독립 가지에는 max를 적용한다.

    반환: (problem_tier, score, info).
    경로 없음: (None, None, {"reason": "no_routes"}).
    모든 경로 제외: (None, None, {"reason": "no_eligible_routes"}).
    """
    if not viable_routes:
        return None, None, {"reason": "no_routes"}
    eligible = [route for route in viable_routes
                if not route.get("uses_powerful_tool", False)]
    if not eligible:
        return None, None, {"reason": "no_eligible_routes"}

    best, best_key = None, None
    for route in eligible:
        route_exec = route.get("execution_extreme", False)
        branches = route.get("independent_branches", [])
        parts = branches if branches else [route]
        results = []
        for part in parts:
            tier, info = classify_path(part.get("critical_discoveries", []),
                                       literacy_high, route_exec)
            e = part.get("execution_load", route.get("execution_load", 0))
            score = decimal_score(tier, info["dominant_s"], e,
                                  info["chain_s_avg"])
            results.append((tier, score, info))
        tier, score, info = max(results,
                                key=lambda item: (TIER_ORDER.index(item[0]),
                                                  item[1]))
        route_id = route["route_id"]
        candidate_key = (TIER_ORDER.index(tier), score, route_id)
        if best is None or candidate_key < best_key:
            best = (tier, score, info, route_id)
            best_key = candidate_key
    info_out = dict(best[2], selected_route_id=best[3])
    return best[0], best[1], info_out
```

- 대체 route는 최종 `(tier, score)`의 최솟값, 독립 가지는 최댓값을 선택한다.
- 모든 경로가 제외된 경우와 경로 자체가 없는 경우에는 공식 점수를 만들지 않는다.
- 코드의 성공 결과 메타데이터를 저장·조회 경로까지 연결한다. Python을 다른 언어로 옮기는 경우에도 고정 fixture의 티어와 소수점 결과가 같아야 한다.

### 17a. 통합본의 필수 회귀 사례

아래 조립 fixture에서 각 M2 발견은 C2/R2/B1/H2이고, E=0, literacy=false, execution_extreme=false다. `is_non_obvious`를 별도로 지정하지 않은 발견은 true로 둔다.

| 사례 | 기대 결과 |
|---|---|
| 연결된 비자동적 M2 세 개 | assembly 발동, T3 / 6.6 |
| 위 세 개 중 하나가 is_non_obvious=false | assembly 미발동, T2 / 4.6 |
| 비자동적 M2 사이에 M0·M1 중간 단계 삽입 | 연결 유지, assembly 발동, T3 / 6.6 |
| 서로 연결되지 않은 M2 세 개 | assembly 미발동, T2 / 4.6 |
| M4→M0→M4 의존 사슬 | 대상 M4 두 개의 사슬로 기본 T5 |
| 같은 길이 사슬 후보의 발견 배열 순서 변경 | 선택 사슬·S 평균·최종 점수 동일 |
| 단일 M5 또는 의존 사슬로 기본 T5 | base_tier와 공통 성공 필드 존재 |
| 기본 T5에서 literacy 또는 execution 조건 충족 | T5 상한 유지, 발동 게이트 기록 |

동일 길이 사슬의 수치 fixture는 M4 두 개씩의 서로 다른 사슬을 둔다. 한 사슬은 각 C0/R4/B4/H0(S=0.6), 다른 사슬은 각 C4/R4/B4/H2(S=1.0)로 두면, 입력 순서와 무관하게 S 평균이 높은 사슬을 골라 T5 / 10.0을 반환해야 한다.

위 검증은 고정 JSON/축/그래프를 이용한 코드 테스트다. 경로 적격성 등 모델의 해석이 필요한 항목은 고정 응답 fixture로 입력 계약을 확인하고, 실제 판정의 적절성은 Part 1의 30문항 파일럿에서 별도 확인한다. 코드 테스트 통과를 실제 AI 평가 통과로 보고하지 않는다.

## 18. 안정성 (Stability)

- 기본: 1회 실행, `strict_calibration=false`. 반복 평가는 기본 작업에 포함하지 않는다.
- `strict_calibration=true` 일 때만 3회 독립 실행 →
  tier 및 C/R/B/H의 **중앙값**으로 deterministic scorer가 최종 점수 계산.
  (최종 score 자체를 투표하지 않는다.)
- strict 옵션은 사용자가 명시적으로 선택했을 때만 적용한다. 이번 30문항 파일럿과 전체 재평가에서 기본으로 활성화하지 않는다.

## 19. 비용

- 문제당 기본 **1회 API 호출**을 원칙으로 한다.
- strict 모드(3회 반복 + 패스 분리 시 최대 9회)는 명시적 옵션으로만 사용.
- 문제 미해결·수동 목표와의 불일치를 이유로 자동 반복 호출하지 않는다. 일시적 API 장애 재시도와 파일럿 이후 비용 승인은 Part 1을 따른다.

## 20. 모델 설정과 프롬프트 승인

- 사용자 지정 모델 표시명: **GPT-6.1 Sol**.
- `reasoning.effort`: **high**.
- 텍스트·이미지 입력, Responses API, 구조화 출력(JSON Schema)을 사용한다.
- 실제 API 모델 식별자와 지원 옵션은 프로젝트 설정 및 현재 공식 API 사양으로 확인한다. 표시명을 임의로 API 식별자로 추측하거나 다른 모델로 바꾸지 않는다.

- 실제 프롬프트는 §1~§14의 원칙과 데이터 계약을 반영해 작성한다. 한 호출 안에 PASS A→B→C 순서를 두고, 짧은 경로 요약과 판정 근거를 받는다. 장문의 사고 과정을 요구하지 않는다.

- 검증 문항의 목표 점수·목표 티어·평가 결론은 AI 평가 입력에서 제외한다.

Part 1 §4의 단계별 완료 보고 형식을 따른다. 실제로 수행한 코드 테스트, 실제 AI 파일럿, 아직 실행하지 않은 전체 재평가를 구분한다. 이미 승인된 범위는 계속 진행하고, 확인이 필요한 단계에서는 사용자가 검토할 실제 결과물을 먼저 완성해 제시한다.
