# 세트 정보 대기 및 학원명 후속 수정

사용자는 이전 배포 후에도 반복 로딩을 보고했고, 실제 오류를 `배치 실패: 세트 정보 응답이 지연되었습니다`로 확인했다. 기존 30초 제한은 오류를 드러냈지만 반복 재조회 자체를 해결하지 못했다.

## 확인한 내용

- 운영 서버의 읽기 전용 조회: 세트 5개/구성원 10개. 08:15:43~08:16:25 UTC 삼성 브라우저의 세트 조회 18건은 모두 HTTP 200, 서버 처리 817~941ms였다. 개별 사용자 세션을 추적하거나 변경하지 않았다. 특정 실패 요청의 네트워크 원인까지 단정하지 않는다.
- 폼·글자·그림 설정을 바꿀 때 매번 전체 세트 레지스트리를 다시 요청했다. 글꼴 loadingdone 알림은 실제 문항 치수가 같아도 다시 배치했다.
- 현재 시험지의 학원명은 기본 폼을 선택하면 버려질 수 있었다. 현재 시험지와 저장된 기본 설정이 다를 때에도 재현했다.

## 수정

- 편집 화면 안에서 같은 문항 ID/수정본 구성에 한해 성공한 세트 조회를 재사용한다. 정렬과 폼 전환은 재조회하지 않는다. 문항 추가/제거·수정본 변경·명시적 최신 버전 확인·다른 편집 화면 진입은 다시 조회한다.
- 실패/취소/잘못된 응답은 저장하지 않는다. 세트 조회 실패를 빈 세트로 대체하지 않는다. 문항 읽기의 권한 확인과 서버 저장 시 세트 검사는 유지한다. 편집 화면 밖으로 캐시를 저장하지 않는다.
- 글꼴/그림 이벤트가 발생해도 실제 문항/머리말 치수가 달라질 때만 재배치한다. 제목 맞춤과 실제 크기 변경 후 재배치는 유지한다.
- 기본 폼 전환 시 현재 학원명을 유지한다. 현재 이름이 없을 때 저장된 설정을 사용하며 명시적으로 비운 이름은 빈 상태를 보존한다. 별도 저장 폼을 직접 선택한 경우에는 그 폼의 설정을 적용한다.
- 복원 실패 안내가 실제 배치 오류를 읽을 수 있도록 상태 요소 식별자를 연결했다.

## 검증

- 이전 코드: 초기 배치 성공 후 추가 세트 요청을 무응답으로 만들면 폼 전환 실패. 수정본: 기본/모던 폼 왕복과 저장 단계 진행 성공, 추가 세트 조회 0.
- 390/1280px 일반/모의고사 4흐름: 학교 선택 기본 펼침·평균 7점 유지. 실제 치수 변화 없는 반복 글꼴 이벤트는 문항 읽기도 다시 하지 않는다. 치수 변화 시 재배치는 작동한다.
- 대명중 실제 본문과 일치하는 로컬 원본 25문항/도형 + 합성 인증/저장소: 초기 복원 후 세트 서버 무응답 조건에서도 390/1280px 모던 폼 배치 성공. 원본 순서 1~25, 100점, 문제9쪽, 저장 버튼 활성화, 학원명 표시 및 추가 세트 조회 0 확인.
- 학원명 전환 5경우, 세트 캐시/대기/세트 의미론/모던 폼 단위 검사 16개 통과.
- 공통 목록 84검사와 출력 계약 통과. 이 PC 병렬 실행에서는 기존 대규모 알고리즘의 10초 성능 기준을 약 0.1초 초과했다. 해당 검사는 단독 실행 7.06초에 통과했고, 전체 목록을 순차 실행해 84개 모두 통과했다. 기준/기대값은 수정하지 않았으며 공식 배포 workflow는 기본 검사 명령을 다시 실행한다.

운영 데이터 변경0, DB migration0, AI0. 실제 휴대폰·실제 회원 저장은 미검증. 학원명 검증은 합성 이름을 사용했으며 사용자가 의도한 실제 이름은 임의로 입력하지 않았다. 코드·검증·배포 상태는 release record에 따로 기록한다.
