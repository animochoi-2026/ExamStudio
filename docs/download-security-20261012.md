# 공식 다운로드 보안 (0.4.34)

별도 출력 서버 없이 기존 웹·Electron 출력 엔진을 유지한다. 보호 수준은 공식 다운로드 추적과 신규 접근 제한이며, 승인된 사용자가 열람 데이터를 수집하거나 출력 코드를 변경하는 것을 완전히 방지하지 않는다.

## 적용과 복구

1. `supabase/migrations/20261012081610_download_security.sql` 설치. 기존 `bank_member` 정의와 PostgREST 설정을 비공개 `bank_security.install_backup`에 보존한다. 기존 정책은 유지하고 차단 상태를 확인하는 restrictive 정책만 추가한다. 초기 자동 차단은 꺼져 있다.
2. 검증한 웹 빌드를 Pages에, Electron 패키지의 resources/app을 기존 실행 위치에 반영한다. 기존 resources/app은 별도 복구 디렉터리에 보관한다. 사용자 자료·로그인·바로가기는 변경하지 않는다.
3. 반영 확인 후 기존 space의 자동 차단을 90%로 활성화한다. 이전 기록을 추측하여 소급 집계하지 않는다.
4. 복구 시 기존 웹·앱을 먼저 복원하고 `supabase/rollback-download-security.sql`을 적용한다. 사용자 식별자·로그·차단 이력은 삭제하지 않는다. R2 및 사용자 자료는 복구 대상으로 변경하지 않는다.

## 정책

- 보안 화면·조회·설정·차단 해제는 고정 연결된 오너만 가능하다. 관리자의 승인·일반강사 이용권 회수 권한은 유지한다.
- R2 파일 접근은 기존 서버의 파일별 권한 검사와 60초 서명 URL을 유지한다. 기존 URL은 잔여 유효시간까지 유효할 수 있고 내려받은 파일은 회수되지 않는다.
- PDF·DOCX·HWPX 공식 출력 시 사용자별 고정 무작위 숫자를 각 문항 끝에 흰색 1pt로 넣고 작성자 메타데이터에 같은 값을 넣는다. 클라이언트에서만 임시 출력 데이터에 적용한다.
- 공개된 최신 원본 학교 시험지의 고유 documentId가 분모다. 발췌·묶음도 연결된 원본 시험지를 집계하며 동일 원본의 재출력은 비율을 늘리지 않는다. 열람·미리보기는 포함하지 않는다.
- 출력 생성 뒤 서버가 공식 제공을 승인한 요청만 성공으로 기록한다. 기기에 저장되었다는 증거가 아니다. 예상 누적 비율이 90% 이상이면 해당 요청을 제공하지 않고 차단한다. 동시 요청은 사용자별 DB 잠금으로 직렬화한다.
- 오너는 자동 차단에서 제외한다. 해제 시 사유와 추가 허용 원본 시험지 수를 명시하며 기존 기록을 지우지 않는다. 누적 허용 개수를 넘고 임계값 이상이면 다시 차단한다.
- 원본 복구용 백업은 원본 바이트를 보존하며 공식 승인·집계와 백업 메타데이터 식별자만 적용한다. 백업 속 원본마다 흰색 워터마크를 넣지는 않는다. 공동 은행과 무관한 오프라인 개인 자료 출력은 기존처럼 가능하다.

## 확인 범위

- 관련 JS 검사 14개, SQL 권한·중복·경계·실패·해제·롤백 검사 통과.
- 격리된 실제 Postgres에서 관리자 거부, 차단 계정 조회 거부 및 동시 요청 차단 확인. 실제 회원 상태는 시험 목적으로 변경하지 않았다.
- 실제 웹 출력 엔진과 Electron PDF 엔진으로 인공 문항 출력. PDF·DOCX·HWPX에서 식별자·작성자 메타데이터 확인, 두 사용자 식별자 분리 확인. PDF 두 페이지 렌더링 확인.
- 웹 출력 시험의 RPC 응답은 인공 응답이다. 실제 로그인부터 파일 저장까지 통합 시험을 새로 수행한 것은 아니다. Word·한글 GUI 육안 출력 확인도 이번 검사에는 포함하지 않았다.
- 최종 웹 빌드와 Electron 패키지 필수 출력 검사를 통과했다. R2 이전·전체 자료·로그인·AI 출제 검사는 반복하지 않았다.

실제 배포 ID, 소스 커밋, 앱 복구 위치는 `release/download-security-20261012.json`에 별도 기록한다.
