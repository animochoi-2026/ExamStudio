# 문제은행 일괄 업데이트 (0.4.6)

## 사용 흐름
관리자 계정 → 문제은행 연결 설정 → 문항 관리 → 일괄 업데이트.
처리 규칙과 학교/시험지 드롭다운·문항 체크박스/누락 항목을 선택한다. 처리 버전·입력 근거가 같은 문항은 제외한다.
대상 수·변경 필드·최대 AI 요청 수·현재 파일 크기를 확인 → 샘플 3개 처리 → 변경 전후와 미해결 사유·미리보기 확인 → 적용.
AI 규칙은 선택 사항이다. 토큰·금액과 재생성 파일 크기는 사전에 확정하지 않는다.
실제 실행은 관리자 PC다. 앱 종료 시 정지하고 같은 PC의 작업 기록에서 재개한다. 현재 파일 검증 중 중단하면 현재 문항 완료 후 멈춘다.
웹 관리 화면에서는 최근 작업 상태와 변경 기록을 조회한다. 웹에서 AI 실행 또는 상시 서버 실행을 가장하지 않는다.

## 처리 규칙
- source-evidence-1: 보존된 인식 번호와 원본 파일명의 명시적 출처만 누락 필드에 적용.
- expected-10-v2-concepts: 기존 BankAnalysis 사용. 네이티브 본문·풀이와 범위로 분석하며 기존 캐시와 확정값을 보호.
- paired-residual-local-v2: 기존 채택 평가와 AI 원점수로 보정. 직접 확정값은 보정하지 않음.
- native-preview-1: 기존 DOCX/PDF 렌더러로 파생 문서·PNG 생성. 수식·도형 원본 유지.
- sha256-native-1: 모든 보존 파일 다운로드·무결성 검사. 없어진 원본을 새로 추측하지 않음.

새 규칙을 추가할 때 registry에 버전·입력 fingerprint·변경 필드·AI 여부를 정의하고, 기존 자료의 재처리와 사용자 확정값 보호 테스트를 추가한다. DB migration과 콘텐츠 작업은 별개다.

## 보존·충돌·되돌리기
작업별 별도 로컬 공간에 DB 문항/수정자/검수값과 실제 파일을 SHA256 검증하여 백업한다. 백업 확인 후 샘플을 만든다.
서버 bank_maintenance_jobs/items가 작업·기준 버전·결과 버전·검수 버전·변경 기록을 보관한다. 행과 RPC는 관리자만 사용한다.
관리자가 등록한 해당 작업의 결과 버전에 한해서 동료 문항의 같은 ID를 유지할 수 있다. 일반 교사 권한은 확대하지 않는다.
등록 직전과 최종 DB commit에서 최신 버전·검수 버전을 검사한다. 완료 응답 유실 시 동일 결과 버전의 commit을 확인해 재사용한다.
되돌리기는 이전 백업으로 새 버전을 만든다. 이후 내용/검수가 변경되면 충돌로 차단한다. 과거 시험지의 pinned revision과 원래 문항·파일은 삭제하지 않는다.
기존 앱이 processing을 포함한 새 메타데이터 키를 버리면 서버가 등록을 차단하고 업데이트를 요구한다. 조회·로컬 편집·출력은 유지한다.

## 서버 배포와 복구
1. 현행 관리자 전체 백업으로 DB 기록과 파일을 함께 보관한다.
2. 202609300011_maintenance.sql을 트랜잭션 안에서 1회 적용한다. 기존 자료 삭제/초기화는 없다.
3. bank-verify Edge Function 갱신: 버전 충돌·업데이트 필요 오류만 명확하게 전달한다. 비밀키 추가 없음.
4. 앱 0.4.6와 웹을 배포한다. 다른 교사 계정의 직접 RPC/Storage 거절을 확인한다.
5. 문제 발생 시 새로운 일괄 실행을 중단한다. 테이블과 감사 기록을 삭제하지 않는다. 확정된 콘텐츠는 개별 되돌리기 계획으로 복구한다.
관리자 백업에 작업 기록도 포함된다. 기존 백업 복원 기능은 파일·네이티브 문항을 로컬 작업으로 복원하고 별도 workspace-backup.json으로 관련 기록을 보존한다. 전체 Supabase 인스턴스/인증 계정의 자동 재생성까지 제공하는 기능은 아니다.

## 검증 구분 및 제한
로컬 PostgreSQL 실제 SQL/RLS + 모의 HTTP/계정 테스트: 교사 소유 문항의 관리자 처리, 일반 교사 차단, 샘플 후 적용, 반복 처리 제외, 원본 소유자/ID 보존, 백업, 보상 버전 되돌리기, 재실행 및 검수 충돌, 구버전 필드 유실 차단.
기존 회귀 테스트 32개 통과. 웹 실제 Edge 브라우저 + 로컬 SQL/모의 계정으로 관리자 메뉴·기존 DOCX/PDF 다운로드 확인.
운영 Supabase 적용·운영 문항 일괄 처리·새 앱의 실제 한글 출력은 별도로 확인해야 한다.
로컬 작업 공간을 잃은 경우 서버의 진행 기록만으로 미완료 렌더링을 재개할 수 없다. 원격 완료본으로 새 계획을 작성해야 한다.
파일이 원격과 백업 모두 없거나 인식 근거가 없으면 미해결로 남는다. 일반적인 파일명 유사도만으로 다른 출처를 연결하지 않는다.
