## 앱 사용 및 보존

현재 열린 새 앱은 운영 R2에 연결됐고 기존 사용자 데이터와 분리된 자료 폴더를 사용한다. `tests/artifacts/r2-freeze/문제공방-R2-실행.cmd`로 이 로그인/자료를 이어서 열 수 있다. 기존 앱/원래 로컬 작업 폴더는 교체하거나 삭제하지 않았다.

다른 PC의 앱 업데이트는 자동 배포하지 않았다. 새 R2 지원 앱과 `production-public-config-r2.json`을 사용해야 한다. 구버전 앱의 Supabase 직접 쓰기는 DB 저장소 정책의 provider 조건으로 차단되며, 오래된 앱을 계속 사용해 새 자료가 원본 저장소에 갈 수는 없다. 다른 PC 설치 완료를 주장하지 않는다.

## 복구

**이미 R2 전용 신규 파일과 수정 이력이 생겼다. 설정만 Supabase로 되돌리지 않는다.** 전체 쓰기 중단·서버 동결 후 현재 DB/참조/설정/R2 목록을 새로 백업한다. 현재 참조 및 삭제 기록을 유지한 채 [README 복구 절차](README.md#자료를-잃지-않는-복구)의 restore-plan → restore-copy RESTORE_FILES_NO_DELETE → restore-verify를 수행한다. 충돌·누락이 없고 신규/교체 파일 및 현행 참조가 검증된 다음에만 provider와 서버 설정을 복구한다. 과거 DB 백업으로 현재 데이터를 덮어쓰지 않는다. 상세 SQL 복구는 전체 과거 초안이 아니라 현재 설치와 맞는 cutover-delta-rollback 및 보관된 실제 함수 정의를 기준으로 한다.

Supabase 원본은 별도 삭제 승인 전까지 보존한다. migration B의 성공 검증은 동결 시점 자료에 관한 기록이며 이후 신규 쓰기의 백업을 대신하지 않는다.
