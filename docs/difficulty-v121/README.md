# 난이도 v1.2.1 — 구현과 실행 상태

사용자 통합 요청서: [원문 전체](request.md). 과거 파일럿은 재현 가능하도록 그대로 보존한다.

이 점수는 실제 학생 집단의 정답률이 아니다. 정규교과 약 70% 이해·기억, 계산 실수, 조건 유지의 어려움, 발상 생성 취약이라는 기준 학생에 대한 construct-based predicted difficulty다. 개념 수·풀이 길이·산술 길이를 발상 난이도와 동일시하지 않는다. 실제 응시 자료는 empirical difficulty로 별도 저장해야 한다.

- 원시 JSON 불변, 독립 분기 max / 대체 경로 min, 기본 T5의 게이트 기록.
- 기존 Codex 구독 실행 어댑터에 명시적 v1.2.1 프로필 추가. 과거 프로필의 동작·해시 유지. API 키로 전환하지 않음.
- 운영 최신 대상 1,266문항 / 52시험지를 읽기 전용으로 확인하고 ID·revision 목록을 비공개 artifacts에 저장.

## 현재 실행 범위 (2026-10-19)

1,266문항의 복구 스냅샷과 해시 검증된 원문·이미지 입력 준비를 완료했다. 사용자 승인 후 구독 계정으로 실제 평가가 진행 중이며, 결과·원시 응답·호출 의도는 Git에서 제외된 `artifacts/difficulty-v121`에 문항별로 저장한다. 완료 단계와 확인된 응답을 재사용하며 결과가 불명확한 호출은 자동 반복하지 않는다.

`20261018164719_difficulty_v121_activation`을 운영 DB에 적용했다. 비공개 staging, 소유자 전용 결과 가져오기, 서비스 전용 원자적 전환·복구 함수를 추가했다. 적용 전후 전체 1,629개 카탈로그의 내용·메타데이터·확정값·파일 해시와 기존 점수 해시가 같고 집계 함수 차이는 0건이다. `20261018170523_difficulty_v121_projection_null`은 업로드 시 보호 키를 JSON null로 남긴 경우 새 평가를 오래된 것으로 오인하지 않도록 표시 함수만 보완한다. 두 마이그레이션은 점수를 활성화하거나 문항을 수정하지 않았다.

웹·데스크톱 공통 표시, 구독 3단계 평가, 동일 입력의 로컬/서버 결과 재사용 연결을 구현했다. 데스크톱 자동 적용 플래그는 전환·배포 준비가 끝날 때까지 꺼 두며 설치 앱·대기열은 바꾸지 않았다. 전체 평가 완료, 외부 검증, 운영 점수 전환, 웹·앱 배포는 아직 완료 상태가 아니다.

[1단계](stage-1-prompt.md), [2단계](stage-2-prompt.md), [3단계](stage-3-prompt.md)와 [실행 범위](approval.md)는 사용자에게 제시했고 `응`으로 승인받았다. 최대 은행 3,798회와 외부 24회, 합계 3,822회이며 같은 단계 자동 재시도는 0회다. 두 Sol 단계의 모델은 `gpt-6.1-sol`이다. 기존 운영 전환 승인도 조건부로 유효하므로 승인 게이트를 다시 만들지 않는다.

## 재개와 전환

- `prepare-difficulty-v121.cjs`: 복구 스냅샷·원문 준비. 운영 점수 변경 없음.
- `run-difficulty-v121.cjs`: 승인·해시·최신 revision을 확인하고 구독 평가 실행. `runner.lock`은 살아 있는 작업과 중복 실행을 막는다. `stop.request`는 현재 문항 저장 후 정지한다.
- 결과 불명으로 중단된 뒤 사용자가 재개하면, `resume-decisions.json`에 그 요청의 입력·응답 해시와 재개 결정을 기록해 해당 1건을 미확인으로 보존하고 나머지를 이어갈 수 있다. 같은 요청을 재호출하거나 성공/실패 확정으로 바꾸지 않는다. 미확인 문항이 남으면 최종 상태는 `staging_incomplete`이며 가져오기·운영 전환은 차단된다.
- `revalidate-difficulty-v121.cjs`: 로컬 검증기 결함을 고친 경우 기존 원시 응답만 재검증한다. AI 0회, 과거 응답과 판정 기록 보존. 승인된 프롬프트·Schema·스코어러·모델 변경에는 사용할 수 없다.
- `import-difficulty-v121.cjs`: 전체 완료 후 원시 JSON을 다시 계산·검증하고 비공개 서버 staging에 멱등 저장한다. 운영 점수는 바꾸지 않는다.
- 최종 전환: 전체 완료·acceptance·실패율 5% 이하·공통 오류 없음·동시 변경 없음 조건을 확인한 뒤 `bank_v121.activate`를 한 트랜잭션으로 실행한다. 부분 활성화 금지.

과거 점수는 복구 스냅샷에만 남긴다. 데스크톱의 기존 보호 검사가 요구하는 과거 난이도 키는 null로 명시해 값이 되살아나지 않게 하며 `processing.displayCorrection` 등 다른 보호 데이터는 그대로 보존한다. 전환 후 같은 평가 입력에 교사가 새로 저장한 조정은 유지한다.

## 정답 검증의 경계

코드는 모델의 solution_validated 값을 신뢰하지 않는다. 객관식 번호·선지 내용, 명시적인 복수 선택, 정규화된 동일 답, 정확한 유리수 동치와 번호가 일치하는 소문항 답을 대조한다. 학년 별칭과 이미 배운 하위 학년 선행 개념, LaTeX 공백·테두리·각도·원주율 기호, 문장 종결 구분점만 다른 경우는 같은 표기로 처리한다. 삼각형 합동·닮음 답은 명시된 하나의 대응 관계와 합동·닮음 조건이 모두 일치해야 한다. 부정·복수 결론·다른 대응점·다른 조건은 통과하지 않는다. 다른 수치·부호·소문항 순서는 통과하지 않는다. 임의의 자유서술·증명·기호식 동치나 단위 변환을 검증했다고 주장하지 않는다. 확인하지 못한 값은 answer_equivalence_unverified 등으로 실패 처리한다. 답의 일치가 풀이 전체의 수학적 증명을 기계 검증했다는 뜻은 아니다.

전체 전환은 미완료 없음·공통 오류 없음·실패율 5% 이하·유효한 결과 구조·시험 버전 일치·복구 스냅샷·acceptance 통과가 전제다. 실패율이 높다고 검증을 느슨하게 만들거나 과거 정답/난이도를 새 모델 입력에 힌트로 넣지 않는다.
