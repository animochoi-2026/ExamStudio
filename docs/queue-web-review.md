# 대량 대기열의 웹 검수

대기열은 인식 결과를 이용해 풀이·분류·업로드를 진행하고 웹에서 검수한다. 원문 확인 경고는 원문 기록과 서버 reviews.recognition에 남긴다. 인식 confirmed 또는 교사 approval을 자동으로 바꾸지 않으며 bank_review_save를 호출하지 않는다. 기존 queue-review-policy.json의 approve_then_web_review 값도 자동 승인에 사용하지 않는다.

재시작 시 보이는 대기열에서 원문 확인만 요구하며 멈춘 풀이 단계를 미시작으로 전환하고 이전 사유를 reviewDeferral에 보존한다. 숨김·제거·취소 항목, 결과 불명, 실제 미완성 풀이, 완료된 단계는 보호한다. 원본 파일·번호 충돌·실제 AI 실패·통신 오류는 원문 검수 경고와 구별한다.

## 서버 폴더 조회 시간 초과

운영 로그의 57014 오류는 bank_entries ID 조회에서 bank_read_entry → bank_read_folder → bank_member 실행 중 발생했다. 소유자 폴더에도 전체 파일 기반 재귀 조회가 먼저 실행될 수 있었다. 후보 migration은 기존 회원·소유자·revision 접근 조건을 CASE로 순서화해 회원인 소유자와 루트 폴더의 불필요한 재귀 조회를 생략한다. 다른 사용자의 폴더와 파일은 기존 검사를 유지한다. 함수 권한·RLS·데이터는 바꾸지 않는다.

## 검증 및 적용 구분

- 실제 AI 호출 없이 로컬 PostgreSQL 환경에서 경고 보존, 풀이·업로드, shared_pending, 검수 버전 0, 재실행 시 중복 없음 확인.
- 기존 운영 기준에서 광범위 검사 109개 중 25개 실패가 재현됨. 범위 기본값·과거 대기열 정책·오래된 저장소 fixture 관련 기존 실패로, 기대값을 완화하지 않음.
- 변경된 검수 계약 검사만 사용자 요청에 맞게 강화. 소유자/다른 교사/비회원 접근 결과 비교와 소유자 경로에서 재귀 함수를 호출하지 않는 검사를 추가.
- 공통 출시 검사 82개 및 출력 계약 통과. 실제 AI·업로드·운영 DB migration·설치 앱 적용은 별도 수행 및 기록해야 함.
