# 4차 파일럿 요청서 — 조립·실행 게이트 강화 (소규모)

## 목적

3차 파일럿에서 문해력 게이트는 18/30으로 작동했으나,
조립·실행 게이트는 0/30으로 전혀 작동하지 않았다.
본 4차는 조립·실행 게이트 강화 프롬프트가 실제로 작동하는지
소규모로 검증한다.

## 프롬프트 변경 사항

### 조립 게이트용 (분해 강제)

기존 예시(2, 12, 13, 19, 20, 24, 30)에 더해, 아래 지시를 프롬프트에 추가한다:

> **발견 분해 규칙:**
> 풀이 과정을 최소 3개의 발견으로 나누어 기록하세요.
> 각 발견은 앞의 발견 없이는 떠올리기 어려운 것이어야 합니다.
> 하나의 큰 통찰을 뭉뚱그려 1개로 기록하지 마세요.
> 예: "숨은 합동 찾기"는 "삼각형 식별 → SAS 조건 확인 → 합동 적용"의 3개로 나눕니다.
>
> 각 발견의 `depends_on`을 반드시 채우세요.
> 비어 있으면 독립된 것으로 간주하여 조립 게이트에서 제외됩니다.

### 실행 게이트용 (학생 기준 강화)

기존 예시(8, 9, 15, 23, 58, 59)에 더해, 아래 지시를 프롬프트에 추가한다:

> **실행 부하 판정:**
> 경우의 수가 15개를 넘거나 계산 단계가 4단계를 넘으면
> `execution_extreme=true`를 검토하세요.
>
> 너에게는 쉬운 계산도 70% 학생에게는 실수 유발 구간입니다.
> 반드시 학생 기준으로 판단하세요.
>
> 전수 확인을 피하는 영리한 방법이 있어도,
> 그 방법 자체의 실행량이 많으면 `true`입니다.
> "나는 이렇게 피할 수 있어"가 아니라 "학생이 이 풀이를 실행하면"으로 판단하세요.

## 대상 문항 (소규모)

전체 30개가 아니라, 조립·실행 게이트와 관련된 문항만 선별한다:

| ID | 선정 이유 |
|---|---|
| V2 | 교사가 G_assembly 기대. 3차에서는 literacy만 발동. |
| V5 | 교사가 G_execution 기대. 3차에서는 literacy만 발동. |
| V6 | 교사가 G_literacy 기대. 3차에서 literacy 발동 확인됨 (대조군). |
| B11 | 2차에서 +5.5 급등. 조립 후보. |
| B14 | 2차에서 +5.5 급등. 조립 후보. |
| B19 | 3차에서 T5/lileracy. 실행 후보. |

총 6문항. 1차·2차·3차 결과는 보존하고 별도 폴더에 저장.

## 판정 기준

- V2에서 `assembly`가 발동하는지.
- V5에서 `execution`이 발동하는지.
- V6에서 `literacy`가 계속 발동하는지 (회귀 확인).
- 은행 3문항에서 게이트가 적절히 발동하는지 (교사 육안 확인).

## 주의

- ChatGPT 구독제로 평가. 별도 비용 승인 불필요.
- 프롬프트 변경 외 스코어러·상수는 변경하지 않는다.
- `prompt_hash`를 새로 기록한다.
- 6문항 결과로 전체 30문항의 성능을 일반화하지 않는다.
