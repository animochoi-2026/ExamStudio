구현 범위
1. 홈에서 기출문제 복원하기 다음에 실전모의고사 출제하기 진입 버튼.
2. 화면 맨 위 기존 기본폼/실전모의고사폼/저장폼 선택과 기본 자동 적용.
3. 자유로운 시험지 이름, A형 객관식 수, B형 객관식/서술형 수, 공통 난이도 비율/목표 평균.
   요청서의 예시 숫자는 고정하지 않았다. 새 문서에서는 문항 수를 직접 입력한다.
4. UUID를 사용하는 유형 추가·삭제, A1/A2/B1 표시 이름. 범위와 배치는 유형 이름을 표시한 팝업.
5. 학교 선택만으로 후보 제한. 학교 수 제한 없음. source.kind=학교기출만 허용.
   교재/AI생성/원문변형을 자동 충원하지 않고 조건도 완화하지 않는다.
6. 추가 유형만 출제 / 특정 유형 재출제 / 현재 모의고사 전체 재출제를 별도 동작으로 제공.
   설정 수정과 학교 추가는 이미 생성된 시험지를 바꾸지 않는다.
7. 저장된 모의고사만의 목록과 명시적 저장. 일반 시험지 저장 API/테이블과 분리.
   이름·폼·개수·난이도·학교·제외 대상·유형 범위·문항 버전·순서·배치·출력 설정을 함께 저장.
8. 저장 모의고사를 이름으로 직접 여러 개 선택하여 모든 유형의 문항 ID 합집합을 제외.
   현재 모의고사의 유형 사이에서 사용하는 공통문항은 제외 대상으로 취급하지 않는다.
9. 기존 시험지 편집기를 팝업에 임베드하여 순서/풀이공간/페이지 이동/PDF/DOCX/HWPX 경로 재사용.
   팝업 편집은 임시 사본에서 수행하고 배치 적용 시 해당 유형만 반영한다.
10. 후보 계산과 실제 출제는 동일 Worker 모델 사용. 후보 안내 이후 실제 출제는 새 스냅샷으로 재확인.

공통문항 선택 방식과 한계
- 기존 bank-exam-model.cjs의 난이도 점수/구간/정수 배분과 exam-scope-allocation.cjs의 부분 단원
  가중치 및 서술형 배분을 그대로 호출한다. 기출 복원에는 자동 배분을 적용하지 않는다.
- 각 유형의 조건 가능성을 기존 흐름/범위 배분기로 먼저 확인한다. 탐색 한도 도달은 부족 판정과 구별한다.
- 모든 대상 유형의 후보 적합도를 함께 집계하고, 유지되는 유형의 문항을 우선하는 공동 순위를 사용한다.
  난이도·형식·단원별 같은 후보 묶음에서 작은 할당량이 큰 할당량에 포함되도록 선택한다.
- 이후 전체 조건을 다시 확인하는 교체로 공유를 개선한다. 일부 유형 사이의 겹침 및 A/B 공유를 처리한다.
- 유형별 후보 18개 이하, 대상 6개 이하인 작은 집합은 정해진 계산 예산 안에서 조합을 전수 비교한다.
  전수 비교가 끝난 경우에만 최대 공유 확인으로 표시한다. 큰 집합이나 예산 소진은 최대 공유 보장 없음.
- 큰 집합의 방법은 유효한 구성을 보존하는 개선 방식이며 전역 최적해를 항상 찾지는 못한다.

문항 식별 및 동시 업데이트
- 제외 기준은 안정적인 bank_questions.id(questionId). revisionId를 제외 키로 쓰지 않는다.
- 기존 question-bank.cjs의 localKey/bindings 및 bank-source-link.cjs의 동일 출처·원본 번호 연결을 유지한다.
  같은 등록 ID를 갱신하거나 기존 원본에 연결해 다시 업로드한 문항도 제외된다.
- 다른 학교나 다른 등록 ID의 내용상 동일 문항을 판정하는 확정된 의미 중복 검사는 확인되지 않았다.
  이번 구현은 그러한 별도 ID를 자동 제외하지 않는다. 학교가 다르면 중복이 없다는 보장도 하지 않는다.
  유형 추론 fingerprint/렌더 캐시는 의미 중복 판정으로 전용하지 않았다. 새 AI 판정/검수 화면 없음.
- bank_mock_snapshot은 STABLE 단일 DB 문장 스냅샷에서 현재 버전, 검수값, 제외 대상 버전을 함께 읽는다.
  변경되는 head를 offset으로 나누어 조회하지 않는다. 분기 충돌 버전은 기존 규칙에 따라 후보에서 제외.
- 선택 항목에 revisionId/scoreSnapshot/catalogSnapshot/solutionSnapshot을 저장한다. 다시 열 때 자동 갱신 없음.
- 추가 출제는 유지되는 유형의 동일 문항을 재사용할 때 그 유형의 고정 버전과 메타데이터를 사용한다.
- 파일 읽기는 기존 권한/해시 검증을 유지한다. 준비 중 권한/파일 오류가 나면 반영하지 않는다.
- 모든 대상 유형의 문항·그림·페이지 준비가 끝난 후 하나의 문서 사본을 한 번에 적용한다.
  브라우저 임시 저장 공간 부족도 적용 전에 실패하여 이전 정상 결과가 유지된다.

미검증·제한
- DOCX 실제 Word/LibreOffice 페이지 렌더링 미검증. 번들 LibreOffice와 Microsoft Word가 없고,
  한글의 DOCX Open은 false를 반환했다. DOCX 생성/다운로드/ZIP/XML/수식 통과와 구별한다.
- 운영 데이터/계정으로 신규 기능을 실행하거나 저장하지 않았다. 운영 권한/네트워크/실제 규모 검증은 후속.
- 독립 등록 ID 사이의 내용 중복은 자동 판정하지 않는다. 큰 후보 집합의 최대 공유도 보장하지 않는다.
- 일반 기기/물리 출력/모든 복잡한 원문 문항 형태에 대한 전수 검증은 아니다.

운영 적용 영향과 후속 조치
- 요청서 2항의 운영 DB 변경 시점 조율에 따라 SQL 및 웹 모두 미적용 상태로 남겼다.
- 먼저 DOCX를 Word가 있는 환경에서 실제 열어 페이지 확인을 마치는 것이 권장된다.
- 승인된 시점에 신규 migration을 먼저 적용하고, 그 다음 검증된 candidate-web 정적 자산을 배포한다.
- SQL은 모의고사 전용 테이블 2개와 전용 RPC를 추가한다. 기존 문항/일반 시험지/폼의 수정·삭제·초기화 없음.
- 저장 모의고사에 쓰인 revision/file을 삭제·prune claim에서 보호하는 트리거를 추가한다.
  이는 새 모의고사가 참조하는 자료 삭제를 차단하는 영향이며, 업로드·새 revision 등록을 막지 않는다.
