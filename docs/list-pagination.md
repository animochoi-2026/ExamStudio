## 조회 개수

| 적용 화면 | 새 조회 API | 페이지 최대 | 43개 검증 결과 |
|---|---|---:|---|
| 문항찾기 | bank_question_page | 20 | 20 / 20 / 3 |
| 검수함 | bank_question_page | 20 | 20 / 20 / 3 |
| 상·중·하·킬러 | bank_question_page | 20 | 각 20 / 20 / 3 |

DB 쿼리에서 LIMIT 20 적용 후 본문·메타데이터를 묶어 반환한다. 전체 결과를 프론트에서 잘라 표시하지 않는다. 문항 정렬은 생성일과 revision ID를 사용한다. 전체 건수는 별도 집계하며 현재 페이지에 속하지 않는 문항 본문/이미지는 목록 응답에 포함하지 않는다. 구버전 열린 화면과 다른 기존 호출 경로를 위해 기존 `bank_search_page`의 계약은 보존했으며 이번 목록은 새 함수만 사용한다.

운영 브라우저에서 검색 1·2페이지 각 20개, 상 20개/총203개, 중 20개/총354개, 하 20개/총146개, 킬러 8개/총8개를 실제 응답으로 확인했다. 운영 회원은 6명이므로 회원·그룹원 목록은 각각 6개 응답이며, 41명 이상 페이지 경계는 격리된 테스트 DB에서 검증했다. 운영 검수함은 공동 미검수 362개 중 현재 페이지 20개만 반환했다.

## 그룹원 선택·저장

페이지와 무관한 user ID 기준 Map에 변경분만 보관한다. 서버에서 현재 그룹원은 처음부터 체크하며, 페이지를 다시 조회할 때 저장 전 변경분을 덮어 표시한다. 저장 이전에는 DB 쓰기가 없다. 취소·닫기는 변경분을 버린다.

저장은 `bank_group_members_save` 한 번으로 처리한다. 그룹 추가·해제·이동 전체를 하나의 트랜잭션에서 검증하고 반영한다. 다른 그룹에서 이동 시 현재/새 그룹과 기존 그룹 제외 사실을 확인한다. 다른 세션에서 소속이 먼저 변경됐으면 전체 저장을 중단한다. 저장 후 그룹 카드 회원 수를 다시 조회한다.

그룹 지정은 기존대로 오너만 가능하다. 관리자는 기존 소속 그룹의 회원 관리 범위를 유지하고 그룹 지정·타 그룹 조회·보안 데이터 접근 권한을 받지 않는다. 새 함수는 익명 접근을 차단하고 서버에서 권한을 검증한다. 기존 회원/그룹 데이터, RLS, 보안 함수 및 스토리지 구조를 바꾸지 않았다. 변경 전후 회원·그룹·기존 권한 함수 해시가 일치한다.

## 검증과 한계

- 실제 마이그레이션을 실행한 PostgreSQL 엔진(PGlite)에서 페이지 개수, 중복/누락 없음, 순서, 그룹 격리, 권한, 전체 롤백, 변경 충돌, 빈 페이지 복귀를 확인했다.
- 브라우저 PC 1280×850 / 모바일 390×850에서 실제 클릭·터치로 목록 3페이지, 이전/다음 비활성화, 필터 초기화/유지, 상세 후 복귀, 빈 결과/오류/로딩을 확인했다.
- 그룹원 여러 페이지 선택 유지, 취소 시 무변경, 여러 페이지 변경의 일괄 저장, 이동 확인 취소/승인, 저장 후 회원 수 갱신을 테스트 DB와 연결된 브라우저에서 확인했다.
- 긴 이름·학원명·이메일, 모바일 가로 넘침, 카드 상단 프로필 수정, 기존 회원 관리 팝업·권한 회귀 검사를 통과했다.
- 공통 검사 84개와 출력 계약 검사를 통과했다. 배포 주소·운영 주소의 공개 자산 92개가 빌드와 일치한다.
- 운영 계정으로 실제 DB 조회와 모바일 크기 브라우저 조작을 확인했다. 운영 회원의 그룹 소속을 테스트 목적으로 바꾸지 않았다. 실제 회원 변경 검증은 격리 DB에서만 수행했다.
- 실제 휴대폰 기기에서의 조작은 미확인이다. 동시 신규 등록/삭제로 전체 결과 자체가 변하는 경우 offset 방식 페이지 위치는 바뀔 수 있다. 정렬값이 같은 기존 항목의 순서는 고유 ID로 고정한다.
- 유료 AI 호출, 실제 출제, 데스크톱 설치 및 사용자 대기열 변경은 없다.
