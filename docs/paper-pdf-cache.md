# 저장된 기출프린트 PDF

기출프린트의 편집용 저장 정보는 그대로 유지하고 문제지와 정답지 PDF를 각각 최신 1개씩 R2에 보관한다. 저장 프린트를 열 때는 전체 미리보기를 만들지 않으며, 편집/미리보기 버튼을 눌렀을 때 준비한다. 최초 다운로드와 수정 후 최초 다운로드만 기존 PDF 생성기를 실행한다.

## 교체와 정리

- 소유자, 저장 버전, 출력 설정, 문항 원본의 내용/파일/검수 정보, 출력 엔진 버전으로 재사용 여부를 확인한다. 정답지 모드 변경은 문제지 파일을 무효화하지 않는다.
- R2의 새 임시 키에 업로드하고 크기와 SHA256을 확인한 뒤 DB의 최신 포인터를 원자적으로 교체한다. 이전 파일은 삭제하고, 실패한 정리는 매분 다시 시도한다. 파일명이 다른 임시 객체가 생길 수 있지만 사용자용 버전 이력은 누적하지 않는다.
- 생성/업로드/저장 버전 충돌 시 이전 파일을 보존한다. 오래된 파일을 최신본으로 내려주지 않는다. 동시에 같은 부분을 생성하려는 요청은 차단한다.
- 파일은 최대 100MB. 생성 예약은 30분, 중단된 업로드는 5분 유예 후 정리한다. 삭제 또는 6개월 만료 시 파생 PDF만 정리한다. 원본 문제은행과 원본 파일은 정리 경로 밖이다.

## 권한과 운영

`bank-paper-pdf` Edge가 실제 로그인 사용자를 확인하고 서비스 전용 `bank_paper_pdf_service`를 호출한다. 익명/일반 인증 사용자는 이 SQL 함수를 직접 실행할 수 없다. 내부 3개 테이블은 RLS와 직접 접근 차단을 사용하며 브라우저용 정책을 열지 않는다. 다운로드 때마다 기존 다운로드 권한, 기록, 워터마크 식별을 유지한다.

마이그레이션 `20261014062942`, `20261014063005`는 각각 캐시 슬롯과 매분 정리를 추가한다. 기존 6개월 시험지 삭제 작업은 유지한다. 정리 토큰은 비공개 DB에만 보관하며 브라우저에 전달하지 않는다. Edge는 기존 R2 설정을 재사용한다.

검증: `tests/paper-pdf-cache.test.cjs`는 실제 SQL을 격리 DB에서 실행해 소유권, 동시 예약, 수정 충돌, 원자 교체, 삭제/만료를 검사한다. `tests/paper-pdf-gateway.test.cjs`는 인증, 전송 실패, 파일 검증, 정리 재시도를 검사한다. 실제 청담중 60문항 저장본은 내용 수정 없이 브라우저 다운로드와 바이트 동일성을 확인한다. 물리적 휴대폰과 운영 자료의 고의 삭제/만료는 별도 검증 범위다.
